## IDEA-001：桌面学习监督助手

### 1. 产品概念

一款放在学习桌上的 AI 硬件助手，在用户学习时识别坐姿不端正、长时间玩手机等情况，并及时提醒。用户可以自己设置允许玩手机的时长，同时通过设备上的 LED 屏幕展示喜欢的图片，让学习监督和个性化桌面陪伴结合起来。

记录日期：2026-10-23。当前状态：首个候选 idea，具体产品方案与实现方式待确认。

### 2. 使用人群与场景

- **学习监督需求**：希望在自习、备考、阅读或桌面学习过程中获得坐姿和手机使用提醒的用户。
- **个性化桌面需求**：希望在桌面设备上展示学习标语、喜欢的照片或其他自选图片的用户。
- **可讨论的市场方向**：面向女性市场，探索展示喜欢的 idol 照片、定制陪伴体验等场景；是否作为主要目标市场及具体定位待确认。

典型体验：用户开始学习前设置允许玩手机的时长，并选择屏幕图片；学习中，设备根据坐姿和手机使用情况发出提醒，平时展示用户喜欢的内容。

### 3. 当前提出的核心功能

| 功能 | 用户期望 | 待确认细节 |
| --- | --- | --- |
| 坐姿识别与提醒 | 识别学习时坐姿不端正的情况，并提醒用户调整 | 需要识别哪些姿态、异常持续多久才提醒、提醒方式与频率、恢复正常后的反馈 |
| 长时间玩手机检测 | 检测用户是否长时间玩手机，超过允许时长后提醒 | 如何判断正在玩手机、如何处理短暂拿起与放下、如何区分手机辅助学习与娱乐 |
| 手机允许时长自定义 | 用户自行选择允许玩手机的时长，设备按设置判断是否超时 | 按单次连续使用还是学习期间累计计时、设置入口、可选范围、暂停与重置规则 |
| LED 屏幕图片展示 | 用户可在屏幕上放自己想放的图片，例如学习标语图片、喜欢的 idol 照片 | 屏幕型号、尺寸、分辨率与显示效果，图片导入方式、格式、容量及切换方式 |

这里的“LED 屏幕”保留当前设想用语，实际显示器件与开发板兼容性待确认，尚未完成选型、接线或显示验证。

### 4. 黑客松原型讨论建议

以下为便于讨论的原型范围建议，是否纳入交付及实现优先级待确认。

围绕“开始学习 → 监督学习状态 → 提醒与调整”的场景，优先讨论以下两个关联工作流：

1. **坐姿提醒**：用户进入学习状态 → 识别坐姿异常 → 按约定条件触发提醒 → 用户调整坐姿 → 更新状态。
2. **手机超时提醒**：用户设置允许时长 → 识别手机使用并计时 → 超过设置时长 → 提醒用户 → 按约定规则暂停、继续或重置计时。

个性化图片展示作为桌面体验的一部分：用户选择图片后在屏幕展示；提醒发生时是否临时切换为提示画面，以及提醒结束后如何恢复图片，待确认。

结合[赛题说明](../赛题/AI硬件赛题说明.md)，确定参赛方案时还需要覆盖以下要求：

- 基础语音唤醒或触发，以及至少两轮连续对话；这与赛后计划的“语音定制”分别安排。
- 至少三类使用情况，以及至少两种赛题列出的硬件反馈方式；具体可从喇叭语音、RGB 灯光、震动、舵机动作中选择，待确认。屏幕展示单独规划。
- 灵机一动平台的智能体配置、能力实际调用，以及至少两个关联工作流的现场演示。

以上是范围讨论依据，尚未验证坐姿识别、手机使用检测、图片显示和平台交互能否在现有硬件上同时稳定运行。

### 5. 黑客松结束后的扩展方向

| 方向 | 初步设想 | 待确认细节 |
| --- | --- | --- |
| 语音定制 | 让提醒与陪伴的语音体验更符合用户偏好 | “定制”具体指音色、提醒文案、角色风格还是其他能力，以及素材来源、平台支持与实现方式 |
| 多人识别 | 从面向单个学习用户，扩展到能够识别多人的使用场景 | 是识别画面中有多个人，还是区分不同用户身份；是否需要分别保存图片偏好、允许时长和提醒设置 |
| 其他扩展 | 持续收集团队讨论中出现的新需求 | 具体需求、用户价值、优先级及是否进入后续版本 |

### 6. 下一轮讨论清单

- **产品定位**：主要解决学习监督，还是进一步突出个性化陪伴？首批目标用户是谁？
- **提醒规则**：什么情况需要提醒，如何避免频繁打断学习？坐姿提醒与手机超时提醒是否采用不同方式？
- **手机计时**：采用连续计时还是累计计时？用户离开画面、放下手机或结束学习后如何处理？
- **配置入口**：时长和图片通过设备按键、语音、手机页面或其他方式设置？
- **硬件与实现**：摄像头摆位、识别方案、屏幕选型、接口资源、接线和供电要求分别是什么？
- **交付范围**：黑客松期间实现哪些功能，哪些保留为赛后扩展？现场如何展示两个关联工作流？
