## 示例原有配置

| 配置 | 原示例内容 |
| --- | --- |
| 依赖库 | `Adafruit_NeoPixel.h` |
| 控制引脚 | `PIN = 6`，Arduino 示例引脚 |
| 灯珠数 | `NUMPIXELS = 16` |
| 数据格式 | `NEO_GRB + NEO_KHZ800` |
| 显示颜色 | `pixels.Color(0, 150, 0)`，绿色 |
| 单次延时 | `delayval = 500`，每更新一颗灯延时 500 ms |
| 行为 | 初始化灯圈后，循环依次设置灯珠为绿色，并调用 `pixels.show()` 更新；循环没有清空灯珠 |

## 与项目接入相关的待确认项

- 原包下载链接指向 [FastLED](https://github.com/FastLED/FastLED/)，但 `.ino` 实际引用 `Adafruit_NeoPixel`。二者是不同库，不能将下载链接当作该示例的依赖声明。
- 开发板手册列出的 WS2812 配置为 GPIO1、默认 8 颗灯珠；此 Arduino 示例为引脚 6、16 颗灯珠。项目实际灯圈数量和引脚待确认，参见[开发板手册](../开发板/灵机XJWB03标准开发板使用文档.md)。
- 此示例未在 LJWB03 / XJWB03 开发板上编译、烧录或运行。具体供电方案、逻辑电平、SDK 适配和运行步骤待确认。

## 项目 SDK 上电点灯测试（2026-10-30）

本项目使用 ESP-IDF 自带的 `led_strip` RMT 驱动，不执行上述 Arduino 例程。`apps/main/main.c` 在震动启动测试之后初始化灯圈，并调用 `bsp_ws2812_fill(0, 16, 0)`：默认 GPIO1、8 颗灯，绿色通道 16/255，启动后常亮，不依赖联网。初始化或刷新失败会记录错误；`ws2812 startup green ok gpio1 leds 8 level 16` 只表示驱动调用成功，实际发光仍需现场确认。

2026-10-30 现场结果：构建、烧录校验和点灯驱动日志通过，用户确认“8 颗灯都亮绿色”，本次低亮度绿色点灯验证通过。其他颜色、动画、高亮度与长期带载运行尚未验证。

本次联调观察到连云、摄像头取流启动后重复异常重启，当前将 `CONFIG_APP_CAMERA_TEST` 暂设为 0 进行隔离。重启根因未确定，不能认定摄像头或灯圈硬件损坏。

### 接线和供电

断电后接线，按实际灯圈背面丝印确认引脚顺序，不按导线颜色推断：

| 灯圈接口 | 连接 |
| --- | --- |
| 5V／VCC | 符合灯圈规格的稳压 5V 电源正极，不接开发板 3V3 |
| GND | 电源负极与开发板 GND，共地 |
| DI／DIN | GPIO1／P1 的控制信号，建议经 3.3V→5V 电平转换后，在灯圈输入处串 330Ω 电阻 |
| DO／DOUT | 单圈测试不接 |

SDK 头文件建议在灯圈 5V 与 GND 间并联 100µF 以上电容，电解电容需确认极性。资料给出的高电平门限为 0.7VDD，5V 供电时不能保证 3.3V GPIO 直连可靠，可使用 74AHCT125 等合适的电平转换器。板上 5V 剩余带载能力、实际电平转换和保护元件安装情况均待确认；独立供电时需共地，避免外部 5V 与 USB 5V 随意并接。用户已确认 8 颗灯亮绿色，实际灯圈型号和具体接线尚未核实。

### 复现步骤

在 `src/firmware/` 下执行 `.\dev.bat build`，成功后按实际串口执行 `.\dev.bat flash -p COM7`，只烧录应用。短按 `EN`，启动后观察整圈是否低亮度绿色常亮；无需联网。串口波特率为 115200。最新构建、烧录与设备日志证据见[首次运行核对记录](../../开发/开发板首次运行核对记录.md)，不能将驱动日志当成实际亮灯验收。
