# Ticko 产品需求与分阶段开发文档

版本：v0.2 开发基线草案<br>
更新日期：2026-11-01（Asia/Shanghai）<br>
维护位置：`docs/产品/ticko最小可交互文档.md`，保留用户指定的原文件名并由原交互草案扩充。<br>
适用人员：产品、固件、算法、平台、结构与验证协作者。

Ticko 面向小学 1–6 年级，以智能坐姿观察、番茄陪学、趣味反馈和宠物成长支持读写习惯。写作业与阅读分别设计；家长预设规则，实体开发板／平台语音链路采用语音输入，H5 触屏面板用于浏览状态与记录，并可直接设置已接入的设备音量与灯圈。休息时邀请眼保健操，摄像头自动观察持续跟随参与及其时长，参与可加分。智能体通过平台产品物模型控制硬件，当前平台配置交付按“自定义产品物模型界面”的字段编写。

本文给出开发顺序、功能规格、状态、数据与接口契约、依赖和验收用例。**先按第 12 节建立模块，再用第 13 节逐项验收；第 14 节未决项只阻塞对应策略或发布，不阻止接口、状态机和模拟测试开发。** 原 v0.2 轮次完成需求细化与源码核对；2026-10-31 追加 H5 本地交互，2026-11-01 又按用户最新要求接入设备音量与灯圈触屏设置，详见第 12.4 节与控制面板专题。真实小程序宿主与硬件按钮效果仍待验证。

### 2.2 直接影响开发的限制

1. 摄像头板 VSYNC 接驱动 CS，当前都对应 GPIO4；默认舵机也使用 GPIO4。必须先确定新映射再并行运行。GPIO8 也与 MPU6050 默认映射冲突。
2. 当前姿态 API 只给“最近完成的一份结果”，没有业务事件队列；反复读取同一结果不得反复累计时间。
3. 姿态输出以身体关键点规则和指标为主，没有眼保健操时序参与判断。眼保健操需早期做可行性实验，见 D0-E。
4. 资源播放会影响智能体音频上传，唤醒也可能停止资源播放；做操音频中的语音暂停／跳过必须专项设计。
5. 原生番茄插件学习模式限制闲聊，暂停仍可能保留该模式；不能假设休息阶段自然允许活动选择与对话。
6. 现有 KV 接口不是可靠成长账本：存储返回、提交错误、容量和多字段一致性必须由 Ticko 适配层处理；不得用共享清库函数重置演示。

## 4 使用流程与业务状态

### 4.1 家长与儿童的操作范围

家长分别准备写作业、阅读的规则。实体开发板／平台语音链路的配置、模式选择、开始／暂停与活动选择采用语音；具体唤醒词沿用实际支持的方式，不因角色名 Ticko 自动改变。Q018 已确认 H5 控制面板通过触屏点击与拖动操作，与实体语音入口并行。

首次配置的具体语音流程、两种模式默认分钟数及家长身份校验方式未冻结。开发阶段可提供明确标记的本地配置／调试入口，仅用于开发验证；实体语音链路遵守 Q016，H5 入口遵守 Q018。H5 当前时长选择、本地兑换不代表家长权限与真实奖励策略已经冻结。开发者在平台网页填写物模型是配置工作。Q010 决定儿童改时长策略，Q011 决定暂停期间姿态行为。

### 4.2 写作业与阅读

| 流程 | 启动示例 | 本轮必须保存 | 后续差异 |
| --- | --- | --- | --- |
| 写作业 | “开始写作业” | `mode=homework`、规则版本、学习／休息时长、会话 ID | 正常书写低头、翻书、取文具的容错与引导文案 |
| 阅读 | “开始阅读” | `mode=reading`、规则版本、学习／休息时长、会话 ID | 书本位置、头肩参考与阅读提醒 |

两个流程共用状态机和成长底层；不复制两套计时与积分实现。每轮采用启动时配置快照；新配置不追溯改写已完成记录。家长改配置是否能即时作用于当前轮见 U03，开发先支持“下轮生效”的可测试路径。

### 4.3 学习与休息主状态

| 状态 | 含义 | 允许的主要操作 |
| --- | --- | --- |
| `IDLE` | 无进行中学习／休息 | 查询、选模式、请求开始、家长配置 |
| `PREPARING` | 正在准备会话／可选开始动作，尚未累计学习时间 | 查询、取消准备；拒绝重复创建会话 |
| `FOCUSING` | 本轮学习计时与姿态观察 | 查询、语音暂停、结束请求 |
| `PAUSED` | 本轮学习暂停，保留已累计时间 | 查询、继续、结束；姿态策略由 Q011 配置 |
| `RESTING` | 一轮学习后休息，可邀请眼保健操 | 查询、开始／跳过活动；继续下一轮须满足活动边界规则 |
| `READY_NEXT` | 休息结束，等待下一轮选择 | 查询、开始下一轮、结束本次使用 |
| `RECOVERY_REQUIRED` | 重启或记录问题，等待核对恢复 | 查询、复核恢复／放弃；不自动补算离线时长 |

`检测不可用`、`正在旋转`、`积分待保存`是独立状态，不把它们全塞进学习主状态，也不自动当作孩子暂停。

### 4.4 状态迁移与冲突处理

| 当前状态与输入 | 处理与目标状态 | 关键约束 |
| --- | --- | --- |
| IDLE／READY_NEXT 收到合法开始 | 创建唯一会话并保存规则，进入 PREPARING；准备结束后 FOCUSING | 可选开始动作必须在学习中保持朝向之前结束；实际开始时再确认“已开始计时” |
| PREPARING 期间视觉不可用 | 记录视觉不可用；动作已停止后仍可进入 FOCUSING | 不能伪装实时坐姿可用，也不让识别失败阻断本地计时 |
| FOCUSING 收到暂停 | 按事件时间结算已运行时长，进入 PAUSED | Q011 未定时用联调配置覆盖两分支；不影响“计时必须暂停” |
| PAUSED 收到继续 | 保留累计，设新运行起点，回 FOCUSING | 不创建新轮次，不重复执行开始奖励 |
| FOCUSING 有效累计达到目标 | 学习只标记完成一次，创建一次休息，进入 RESTING | 学习结算与休息邀请都要去重；存储失败记录待处理，不虚报积分 |
| RESTING 本次首次进入 | 持久化本次邀请标记后邀请一次 | 绑定 `rest_id`；查询、重连和重复进入事件不重复播邀请 |
| RESTING 结束且无进行中眼操 | READY_NEXT | 不自动开始学习；用户确认后下一轮 |
| 休息到点但眼操进行中 | 标记休息到点；暂不并行开启新学习 | 按 U06 选定的边界策略终结或完成活动，开发保留“活动完成后等待下一轮”路径 |
| PREPARING取消、FOCUSING／PAUSED结束学习 | 停止当前作业，归档未完成会话后回IDLE | 不新建休息或完整轮次奖励；记录的部分时长如何再利用等待U04 |
| RESTING结束眼操 | 活动记CANCELLED／已完成终态，留在原RESTING | 不创建新休息或新邀请，不自动把未通过活动记为完成 |
| 任意非空闲阶段结束本次使用 | `END_USAGE`停止计时／音频／观察／动作，归档后IDLE | 保留已提交成长及应处理结算；保存失败进入RECOVERY_REQUIRED并报告，不假装已归档 |
| 重启读到未完成会话 | RECOVERY_REQUIRED | 断电期间不推断学习、跟做或离席，不自动重播本次休息邀请 |

事件统一由总控串行处理。到点与暂停同时发生时，先按命令携带的单调接收时间更新有效累计：已达目标只完成一次，否则暂停；相同时间优先终态结算。停止命令不得撤销已提交完成记录。此为可测试的工程仲裁约定。

“结束学习”与“结束本次使用”的命令必须分开路由；休息／做操中若只说含糊的“停一下”，先依据当前上下文明确作用对象，不同时停止多个无关实体。具体角色权限在U02冻结，不由语音自称身份决定。

## 5 坐姿与实体反馈规格

### 5.1 姿态结果与持续判断 FR-05 FR-06

1. 仅使用真实摄像头输入；静态图、人工事件与回放只用于标记清楚的模块测试。
2. 每份结果必须附采集时间、帧 ID、错误／可用状态和机位版本。只有属于当前机位、未处理过、未过期的有效结果才能推进业务。
3. 短暂取物、翻书不直接提醒。有效偏离样本在允许间隔内持续达到 `warn_after_ms` 才触发；遇到过大观察间隔或未知，不把空档全部补成持续偏离。
4. 恢复需要新的有效结果持续达到 `recover_after_ms`，再解除；提醒受 `cooldown_ms` 限制，冷却不阻止解除。
5. `no_person`、`unknown`、推理错误、摄像头故障、过期和旋转分别可观察；它们不生成“坐姿错误”“孩子偷懒”或虚假恢复事件。
6. 写作业、阅读的参考／阈值可独立配置，但最终差异须经真人场景验证；自然低头不能简单等同于错误。
7. 首版先验收明显侧倾／身体侧偏之一；更多姿态是后续扩展，不为满足“三类情况”强行同时做三种姿态。

### 5.2 LED 与语音反馈 FR-07

LED 眼睛以明暗与闪烁表达。实际灯珠分组需确认，不能默认能显示图形表情或两眼独立动画。

| 业务事件 | 建议表现 | 优先级与验收 |
| --- | --- | --- |
| 学习正常 | 低亮稳定或缓慢明暗，不主动长聊 | 不遮盖当前不可用／暂停状态 |
| 持续偏离 | 柔和明暗／短眨，必要时一句具体语音 | 学习中不转壳；不使用高频连续催促 |
| 恢复 | 解除提醒，必要时“调整好啦” | 不按每次恢复加分 |
| 暂停／检测不可用 | 清楚可区分的状态表现 | 不用开心动画掩盖不可用 |
| 完成／升级 | 一次短表现，可在允许阶段旋转 | 先确认结算成功再播报具体已获积分 |
| 眼保健操 | 柔和陪伴，主要通过音频引导 | 不要求儿童盯着 LED 模仿动作 |

具体亮度／节奏见配置表，仍属待确认映射。开发先实现有界非阻塞动画与统一优先级：故障／取消处理优先，姿态提醒其次，阶段提示其次，庆祝／装饰最后。低优先动画不得阻塞计时、音频控制或释放取消请求。

### 5.3 旋转与摄像头机位 FR-08

- 只在开始、结束、休息或升级时允许动作；FOCUSING 禁止新转动请求。庆祝若在学习中产生，只播允许的 LED／声音或延迟动作，不擅自转壳。
- 每个动作有 `motion_id`、有界目标／速度／超时；不发无限旋转，不把一个舵机解释为多个自由度。
- 舵机开始动作前，机位状态转为 MOVING，并使旧候选偏离和恢复累计失效。动作期间的图像不判断儿童姿态，也不累计眼操参与。
- 回参考朝向后进入 SETTLING，等待配置的稳定条件及新有效结果，再设为 READY。软件记录角度不是物理到位证明。
- 移动／恢复不自动暂停已有学习计时；它们不能产生额外积分，也不能取消恰好到点的正常学习结算。
- 自动眼操观察期间建议固定朝向，休息旋转放在活动前后；活动、音频与动作由总控互斥编排。
- 引脚、供电、限位、回中和结构尚未验证前，开发配置禁用实际舵机输出，仅模拟动作事件；完整产品验收仍须实测旋转与机位恢复。

## 6 休息眼保健操规格

### 6.1 邀请与选择 FR-10

每次休息分配唯一 `rest_id`；邀请最多发一次，并持久化 `invitation_issued`。孩子说开始才创建活动，跳过后本次休息不自动重新邀请；重新查询状态／平台重连不重播邀请。

在U07未允许重试／重做前，同一休息最多关联一个 `activity_id`。即使换新的command_id重复开始，也返回已有活动及其状态，不重新创建可领奖来源。若后续允许重试，用同一activity_id下的attempt_id区分尝试；是否允许通过后再做及再次奖励必须另定规则，不能绕过去重。

邀请标记应先保存再播放。掉电发生在保存后、播报前时，恢复后允许展示活动入口，但不自动补播，以守住不重复邀请。存储失败要显示或记录失败，不能反复播邀请冒充新休息。

### 6.2 活动状态与音频 FR-11

| 活动状态 | 含义与后续 |
| --- | --- |
| `NOT_OFFERED`／`OFFERED` | 未邀请／已邀请，等待开始或跳过 |
| `PREPARING` | 创建 `activity_id`，准备音频、朝向与观察能力 |
| `OBSERVING` | 播放引导并采集参与证据 |
| `PAUSED` | 暂停活动；是否可续接及音频行为按配置验证 |
| `EVALUATING` | 播放结束或观察结束，汇总有效证据；还未判通过 |
| `PASSED` | 达到已验证的参与条件，可申请一次结算 |
| `UNCONFIRMED` | 看不清／证据不足，不能确认；不解释为孩子没做 |
| `SKIPPED`／`CANCELLED`／`ERROR` | 跳过／取消／播放或识别故障，不自动记为通过 |

资源音频采用经家长确认的规范版本。开始前可提示清洁双手，不由大模型临时编造穴位或疗效。实际音频版本、时长、格式、来源和可离线播放范围写入资源清单；当前播放以实际解码支持为准，不能默认任意 MP3 可用。

音频结束只改变播放状态，再进入 EVALUATING；重复结束回调不得重复提交判定或积分。音频失败、唤醒中断、跳过和活动取消必须发送可区分事件。播放期间的语音接入需在 D5 解决现有音频占用冲突，不能只在提示词里写“随时说暂停”。

### 6.3 自动参与判断 FR-12

已确认目标是**持续跟随的参与过程与有效时长**。不评价穴位、按摩力度、标准程度或健康效果；也不以孩子自报、家长确认静默替代自动识别。

算法适配层输出带时间边界的观察窗口，至少区分：`FOLLOWING`、`OTHER_ACTIVITY`、`NO_PERSON`、`UNKNOWN`、`ERROR`。具体可观察动作证据、特征及分类方法由 D0-E 验证；普通坐姿“正常”不等于跟做，只有人在画面内也不等于跟做。

有效参与时长按合格观察窗口的**时间并集**累计，窗口必须同时满足：

- 属于当前 `activity_id`、同一 `boot_id` 与有效机位版本，采样时间位于实际观察区间。
- 证据为新鲜且达到验证条件的 FOLLOWING；不是同一帧／结果重复读取。
- 未处于活动暂停、设备旋转、观察失效或超出允许间隔的时段。
- 不把推理等待时间、两个孤立正样本之间的长空白、遮挡、旧帧自动补算为参与。

例如模拟窗口 `[0,2]`、`[1,3]` 秒合并后只累计 3 秒，不是 4 秒；区间 `[3,10]` 没有可接受证据时不补算 7 秒。该例用于算法与状态接口测试，不是已证明摄像头能生成这些窗口。

通过条件须同时配置并验证：最小有效参与时长、所需时间覆盖、最大证据间隔、可用置信度与最大结果年龄。任一必需条件未定／算法不可用，返回能力不可用或 UNCONFIRMED，不能仍自动发参与分。允许的重试、保留进度与后补分策略见 U07。

覆盖率分母采用选定音频／活动版本定义的应观察时长或观察区间，不采用“仅剩有效帧的时长”；缺帧、UNKNOWN和遮挡不能缩小分母提高通过率。暂停不增加应观察时长，取消／跳过不把计划活动缩短成已完成短活动。音频引导段、正式做操段与观察区间的对应关系在资源版本中冻结。

观察结果建议表述为“摄像头观察到参与”。参与未通过时不扣已有积分、不用生病／掉级责备孩子；这不等于直接奖励未确认活动。

### 6.4 活动与休息边界

休息的倒计时与眼操活动分别记录。每个活动绑定发起它的休息；旧休息的迟到结果不能计入新休息。休息到点但活动还在运行时，只能走一种已配置边界策略，不能同时进入新学习和继续旧观察。

开发提供“结束当前活动后进入 READY_NEXT”的路径用于联调；是否延长休息、是否允许提前结束、完成后如何使用剩余休息由 U06 冻结。跳过眼操保留正常休息，不扣已有成长，不要求强制做操才能继续下一轮。

## 7 成长与持久化规格

### 7.1 分开计量 FR-13

至少分别保存：完成学习轮次、已确认眼操参与次数、有效参与时长、积分账本、等级／解锁项。眼操参与不增加“完成学习轮次”；轮数、秒数和积分不得直接相加。

学习到点生成 `focus_completed` 来源事件，眼操 PASSED 生成 `exercise_participation_passed` 来源事件。去重身份使用 `(data_scope, source_type, source_id)`；规则版本作为该来源固定的计算依据，不进入可变化的去重键。同来源携不同规则版本重送时返回既有结果或冲突，不新发第二笔奖励。

具体分值、是否共用积分账户、等级门槛、每日上限、初始眼睛状态仍未确认。实现采用规则表，未配置不得伪造积分；开发可用第 10 节的模拟规则验证账本。原有 1／3／6／10 轮示例保留为历史建议，不作为已确定等级表。

### 7.1.1 H5图鉴与路演规则（Q021，2026-10-31）

用户本轮两张图片明确七种脸、基础／小熊／纪念版外形；后续回答“为了路演方便，改为可以随意切换等级规则”。当前H5提供两种展示方式：

- **按专注记录**：等级从成功保存的完整focus来源去重计算，分钟与轮数分别显示；不从币余额计算，花币不降级，存储失败的待提交轮次暂不计成长。候选演示门槛为累计0／1／3／6／10／15／21轮，具体正式门槛仍属U09待定。
- **路演切级**：图鉴内直接点1–7级，立即展示该阶段脸和对应已解锁表情；清楚标记路演演示。实际轮次、分钟、币账本及真实已选表情不变。路演装备仅在内存中，切回按记录或刷新恢复真实记录和原装备，不生成伪完成来源。

七种表情：无色暗色双竖眼、初见白双竖眼、选色蓝紫双眼、熟悉蓝双竖眼、回应一竖一横、默契双弧笑眼、伙伴爱心与弧眼。升级解锁后，由孩子明确点“使用”才保存；锁定表情允许临时预览但不能装备。默认无色，不自动替孩子装备新解锁脸。

皮肤和表情分别展示。小熊版采用奶咖色圆耳与绒毛材质；纪念版按用户参考采用橙轮廓／侧翼、白内脸、橙色wink和头顶闪电，皮肤内允许参考橙色，不改变全局薄荷界面。未设计项只显示不可点的待解锁框。当前变体皮肤只试穿，退出图鉴／下拉／结束预览即恢复基础版与当前模式已选表情，不创建新购买或扣币。旧配色purchase历史保留以回放余额，旧已装备配色迁回基础版，不清空学习记录或钱包；完整云商城及正式皮肤解锁条件未因此交付。

本轮只实现浏览器图鉴、模型外观及路演能力；实体LED、舵机、云积分和识别仍单独验收。代码与操作见[成长图鉴与路演说明](../开发/Ticko成长图鉴与路演切级说明.md)。

### 7.1.2 选色与完成庆祝（Q022，2026-10-31）

用户确认六种可选颜色为蓝、黄、紫、绿、粉、橙，作用于眼睛，身体不随色板染色。本次H5沿“选色”阶段在Lv3开放全部六色，这是按既有演示阶段实施的配置，不另行冻结正式逐色门槛。图鉴点选色卡即展开色板；等级不足可看但不可用，达到等级先预览、再明确使用。路演等级同样控制解锁，颜色只保留在演示内存；切回按记录或刷新恢复原色。旧数据未主动选色时保持原灰／白／蓝紫默认脸，只有明确使用后才保存覆盖色。降到未开放阶段暂停应用自选色。

完整专注的当前新来源成功保存后，才发一次完成庆祝；存储失败不庆祝，后补成功提交仍按ID去重，旧账本恢复、暂停、重置、休息完成不制造庆祝事件。模型身体与脚分组：壳、面屏、眼睛、头饰随身体倾斜跃起，底座保持位置／旋转／缩放不变，结束回原姿态。减少动态效果设置下只做柔和反馈。路演提供单独“预览庆祝”，不创建完成记录或奖励。

纪念版默认面屏为淡黄，小熊默认眼睛为鹅黄；变体试穿保留自己的设计默认色，退出恢复已选表情及颜色。此动画仅H5程序模型，实体舵机没有增加跳跃能力，外部GLB无身体／底座绑定时不强制拆分动画。

### 7.1.3 专注界面锁与文案精简（Q023，2026-10-31）

H5处于focus＋running时默认锁定所有页面控件：品牌入口、图鉴、设置、3D点击／拖转、上拉把手、功能面板、快捷按钮和页面快捷键均不可操作；唯一可用的是现有右上按钮下方的锁控件。点击解锁只恢复界面交互，计时继续；可以再次上锁。每次开始／继续专注重新默认锁定，暂停／完整完成／进入休息时解除，解锁标记不持久化或跨轮继承。正常刷新仍按既有规则恢复为暂停，不因刷新自动补计或自动开始。浏览器／操作系统自身控件不属于页面锁。

锁定时收起功能面板，保持计时可读；模型取消锁前尚未结束的拖动。宿主离线弹窗在锁中延后显示，避免遮住唯一解锁键；解锁且仍离线时按原逻辑显示。此锁只影响H5交互，不新增实体语音权限或硬件指令，Q010／Q011等未决事项不因此冻结。

图鉴删除“试穿一会儿…”“点一下试穿”“原本的样子”等及同类装饰文案，保留名称、解锁状态、必要等级限制、路演标识、真实统计与明确操作。纪念版整个方体改同款橙色（顶部／侧面／背面都覆盖），淡黄面屏加立体中空橙边框；底座仍为脚，运动绑定不变。

### 7.2 一致性与提交顺序 FR-14

积分总额、来源去重、等级与解锁必须形成可恢复的一致提交，不能“先加积分，再另写已领奖标记”后就认定幂等。建议使用版本化快照配合提交序号／校验与可恢复写入；也可采用验证等价的日志事务方案。具体存储实现由 D1 确定并通过 AC-26。

至少支持 `PENDING`、`COMMITTED`、`ERROR` 的结算状态。成功提交后才回报“已获得 X 分”；存储失败时保留待结算事件并重试，不重复增加。表现／播报失败不撤销真实完成记录，可查询已提交积分，但不能通过重复动画再次发奖。

账本清理前应保留可验证的去重依据；容量满时报告 `STORAGE_FULL`，不得清空去重记录后让旧事件再次中奖。容量与保留期作为 U10 配置，发布前确定。

### 7.3 重启恢复

保存模式与规则版本、活动／休息标识、暂停快照、邀请标记和结算状态。重启后新建 `boot_id`，此前单调时间不能与本次直接比较。

恢复已提交成长；未完成学习／眼操进入恢复待核对，不将关机时长补算。具体恢复为暂停继续还是结束本次使用由 U05 确定；开发先完成 RECOVERY_REQUIRED 与保留旧记录的能力。损坏／版本不兼容时报告原因，不自动擦整片 NVS 或配网信息来掩盖错误。

存储命名空间应与网络凭据、产品绑定隔离。可分别使用 `ticko_prod` 与 `ticko_demo` 命名空间，通过独立适配封装；不依赖共享KV自动隔离。演示重置仅清 `data_scope=demo` 的 Ticko 数据，不能调用共享 `qm_kv_clean()` 清除其他模块内容。

## 8 内部数据与命令契约

本节是**建议新增的 Ticko 内部契约**，便于固件、算法、调试和平台分别开发；不是灵机已有物模型、SDK API 或已发布接口。对外配置先按[自定义产品物模型界面](../开发/自定义产品物模型界面与开发逻辑.md)填写，再在 D4 从 Ticko 实际产品导出核对 `siid/piid`、参数类型、权限及语料，不能仅复制旧模板编号。本轮用户提供版本 3 示例（9 服务、31 属性），其中 `duoji` 舵机服务无属性，尚不是完整 Ticko 控制定义。

### 8.1 数据对象

| 对象 | 最少字段 | 不变量 |
| --- | --- | --- |
| `ProductRules` | `schema_version/config_id/rule_version/mode_rules/permission_policy/pause_posture_policy/reward_rules` | 未确认规则显式 UNRESOLVED；新版本不改写旧记录 |
| `ModeRules` | `mode/focus_ms/rest_ms/posture_profile/resource_id` | 两模式分开配置，时长为正整数且在已配置上限内 |
| `FocusSession` | `session_id/mode/rule_version/state/target_ms/accumulated_ms/run_anchor/boot_id/completion_status` | 暂停不累计；每轮最多一次有效完成 |
| `RestContext` | `rest_id/parent_session_id/state/remaining_ms/invitation_issued/activity_id` | 一次休息一个邀请标记；跳过不会产生新邀请 |
| `ExerciseActivity` | `activity_id/rest_id/resource_version/state/heading_epoch/valid_participation_ms/evidence_summary/decision_version` | 归属不变，播放与参与判定分开 |
| `ObservationWindow` | `observation_id/activity_id/boot_id/frame_ids/start_ms/end_ms/heading_epoch/label/confidence` | 新鲜、未重复、同一活动与机位；区间不倒置 |
| `RewardReceipt` | `receipt_id/data_scope/source_type/source_id/rule_version/unit/delta/status/snapshot_revision` | 同来源一次有效结算；单位不混加 |
| `GrowthSnapshot` | `focus_rounds/exercise_passes/reward_totals/level/unlocks/revision` | 来自 COMMITTED 记录，不能凭大模型文案改变 |
| `FeedbackJob` | `job_id/source_event/kind/priority/expiry/cancel_token/motion_limits` | 过期／已取消不执行，旋转受业务状态约束 |
| `Capabilities` | `camera/pose/eye_participation/eyes/servo/audio/voice/cloud/storage/execution_source` | 使用 UNAVAILABLE／UNVERIFIED／READY／ERROR 等状态；来源区分real／simulated，不能以文件存在或模拟器代替真实READY |

ID 须在设备重启后仍能区分历史来源；可用持久化设备计数与随机标识等实现，不能仅用开机秒数。开发模拟 ID 必须带 demo 标记，不能混入真实账本。

数据类型约定：`*_ms` 和运行时累计采用非负64位整数，单调时间必须与boot_id一起解释；计数／版本为非负整数，积分采用带单位且做溢出检查的整数。ID作为不透明字符串处理，内部建议最长64字节，所有读写检查长度／容量。枚举不接受任意文本，置信度统一归一到0–1并附模型版本；未获取值用明确缺失状态，不能用0同时表示未知与有效零值。

### 8.2 命令与回执

所有输入先进入总控命令队列，带 `command_id`、来源、关联实体 ID、接收单调时间和期望状态版本。角色标签应来自可信适配入口，不能因为语音里自称家长就直接授予配置权限；正式角色校验见 U02。

| 命令 | 输入与主要前提 | 应答或结果 |
| --- | --- | --- |
| `GET_STATUS` | 当前会话／活动 ID 可选 | 实际状态、能力、剩余时间、已提交成长、错误与版本 |
| `START_FOCUS` | `mode`，对应配置完整，处于可开始状态 | 同一命令只创建一次会话；准备／实际开始分开回报 |
| `PAUSE_FOCUS` | 当前 `session_id`，正在学习 | 暂停计时，按 Q011 策略处理姿态；重复暂停返回当前状态 |
| `RESUME_FOCUS` | 当前暂停会话 | 保留进度继续；角色与恢复提示方式待规则确定 |
| `END_FOCUS` | 正在准备／学习／暂停的会话与请求原因 | 停止并归档后IDLE；未达目标不当完整轮次，部分进度按U04 |
| `END_USAGE` | 任意进行中学习／休息／活动，明确结束本次使用 | 停止全部当前作业并归档后IDLE；保存失败进入恢复状态，已提交成长不撤销 |
| `START_EXERCISE` | 当前 `rest_id`已邀请且未跳过、无其他活动；音频／识别能力可用 | 每rest最多创建一个activity；已有活动返回既有状态，不能换命令ID再次创建；重试受U07约束 |
| `SKIP_EXERCISE` | 当前休息，活动未开始 | 本休息标记跳过，不重新邀请，不增加参与分 |
| `PAUSE_EXERCISE/RESUME_EXERCISE/STOP_EXERCISE` | 当前活动 ID | 音频与证据区间同步改变；STOP取消未完成活动并回原休息，不重新邀请，已提交终态不撤销；语音通道须联调 |
| `SET_PARENT_RULES` | 已验证家长入口、完整新规则与版本 | 校验并保存；当前轮是否即时改变按 U03，不静默覆盖 |
| `SET_THEME` | 已提交解锁项且设备支持 | 应用实际表现；不存在／未解锁返回明确错误 |
| `RESET_DEMO` | demo 范围、空闲状态及调试入口 | 只重置模拟业务记录，不清网络／绑定／正常数据 |

回执区分 `accepted`（已入队）、`applied`（状态已生效）、`rejected` 与 `pending`。智能体只能依据 applied 或已提交结果确认完成；accepted 不能被说成“设备已执行”。超时后先查询状态／原命令结果再重试，使用相同 command_id；不创建新 ID 盲重试开始。

同 ID、同参数返回已知结果；同 ID、不同参数报 `COMMAND_CONFLICT`。旧 session／rest／activity ID、旧配置版本的修改请求不得作用于新实体。外部不能绕过状态机直接让舵机在 FOCUSING 转动。

错误至少可区分：`INVALID_STATE`、`INVALID_ARGUMENT`、`NOT_AUTHORIZED`、`CONFIG_INCOMPLETE`、`CAPABILITY_UNAVAILABLE`、`OBSERVATION_STALE`、`STORAGE_ERROR`、`STORAGE_FULL`、`COMMAND_CONFLICT`、`TIMEOUT`。这些为内部错误码草案，由适配层转为平台实际支持的应答形式。

### 8.3 事件与记录

事件至少包含 `event_id/type/boot_id/captured_or_occurred_ms/received_ms/entity_id/rule_version/state_version`。视觉事件额外携带 `frame_id/heading_epoch`；音频事件携带 `playback_id/activity_id/media_position`。

主要事件：`focus_started/paused/resumed/completed/ended`、`rest_entered/invited/expired`、`posture_deviation/restored/unavailable`、`motion_started/settled/failed`、`exercise_started/paused/playback_finished/evaluated/cancelled`、`reward_pending/committed/failed`、`capability_changed`。

日志应能串起“输入—判定—执行—保存—回报”，不保存真实凭证或不必要的音视频。事件、命令、业务实体和视频帧是不同标识，不能用一个编号同时充当全部归属。

### 9.3 计时与平台开发路径

开发约定由 `ticko_session` 作为唯一业务状态源，按单调运行时间计算累计与截止点。首期按自有会话状态机＋适配层实施；底层可复用经过核对的组件，但不得同时运行两套各自决定完成／休息的时钟。

ESP-IDF 的 [`esp_timer_get_time()`](https://docs.espressif.com/projects/esp-idf/en/v5.4.1/esp32s3/api-reference/system/esp_timer.html)提供启动后的运行时间；重启／深睡后的时间基准不能直接当作原会话连续时长，回调保持短小，业务通过队列处理。网络对时只用于显示日期与记录，不改变已累计学习时长。

平台先用自建工作流／实际设备控制映射到内部命令。若继续使用原生番茄插件，D4 必须验证学习／暂停／休息三阶段的命令放行与 start／stop 双向同步，再决定接入该适配器；不能把插件模式限制留到整机收尾才处理。

[NVS 官方说明](https://docs.espressif.com/projects/esp-idf/en/v5.4.1/esp32s3/api-reference/storage/nvs_flash.html)描述键值存储与提交接口；本文要求的成长事务、去重与快照恢复是 Ticko 额外业务职责，不能因为使用 NVS 就声称多字段更新天然满足账本一致性。

## 11 非功能要求与失败处理

### 11.1 工程验收目标

以下为待验证的工程目标，不是历史实测成绩。

- 主逻辑用可注入时钟测试，模拟暂停／继续／到点结果可精确复算；60秒本地计时实机误差目标不超过1秒。
- 本地命令 accepted 回执目标在1秒内；耗时动作随后单独回报 applied／失败，不能为等待动作阻塞队列。云端网络耗时单独测量，不承诺所有网络条件下1秒完成。
- 整机目标连续运行30分钟、完整流程重复3次，无明显卡死、异常重启或重复结算；眼操识别、语音／播放、LED与已接通动作按实际组合测试。
- 姿态与眼操验收必须给出样本说明、真人／场景覆盖、误报／漏判统计、数据有效性和测试版本；通过指标在实验前登记，不能只展示调参用的同一段视频。
- 队列、帧缓冲、账本和日志容量有上限；满时记录具体降级／错误，不覆盖未结算数据或无限积压旧帧。

### 11.2 故障行为

| 故障／情况 | 必须行为 | 不允许的替代 |
| --- | --- | --- |
| 网络断开 | 已开始的本地计时继续；显示离线，在线命令／播报按真实能力返回不可用 | 猜测云端已下发或声称任意离线语音可用 |
| 摄像头／模型失效 | 姿态或眼操进入不可用／无法确认；计时保持其已有状态 | 当坏姿态、正常恢复或参与通过 |
| LED／马达／舵机错误 | 停止故障输出，记录并尽量用其余已接通方式表达 | 只有日志却声称硬件反馈成功 |
| 音频播放失败 | 活动 ERROR／可恢复状态，停止由播放推进的观察条件 | 结束即自动算完成 |
| 积分写入失败 | 保留待结算并报告；重试可恢复且去重 | 先口头承诺已到账或重新加分 |
| 配置无效／策略未定 | 标明未配置；开发注入测试策略，产品对应功能不放行 | 无声使用建议值作为正式规则 |
| 状态／结果归属不符 | 丢弃并说明原因，不改当前实体 | 旧会话的结束影响新会话 |
| 重启／时间跳变 | 恢复已提交记录，未完成活动待核对，不补算关机时长 | 把跨boot单调时间直接相减 |

业务持久化默认只记录必要配置、事件摘要、有效时长与积分，不保存原始儿童音视频。算法样本采集如需保存图像，应单独确定用途、保留范围与团队可用目录；不把真实密钥、儿童图像或含凭证备份混入源码提交。
