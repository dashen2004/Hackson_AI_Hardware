# AI＋硬件：桌面智能伙伴赛题说明

> 来源：用户提供的赛题正文，整理日期：2026-10-21。本文保留赛题要求，仅调整 Markdown 排版与章节编号。项目的具体产品场景与实现方案仍待确认。

## 1. 赛题方向

参赛队使用 LJWB03 核心板及配套模块，结合[灵机一动平台](https://www.ljyd.cn/)，设计一款面向具体场景的桌面智能伙伴。产品形态不限，可以是桌面玩偶、智能台灯、学习伙伴或其他桌面设备。

参赛队应围绕一个明确的核心产品场景和一个具体用户问题进行设计，例如学习陪伴、情绪安抚、专注提醒、老人关怀或亲子互动。在同一核心场景下，至少设计两个相互关联、可以现场运行的工作流，例如“开始专注”和“专注结束提醒”。不要求同时覆盖多个场景，重点考察一个场景内的完整闭环。

## 2. 题目背景

很多桌面设备能够执行简单动作，但对用户的语言、状态和具体使用场景理解有限，难以在连续使用中给出合适反馈。本题鼓励参赛队使用 LJWB03 核心板、SPI 摄像头、麦克风、喇叭及配套模块，结合灵机一动平台，完成语音交互、坐姿识别和硬件反馈，打造能够理解用户并持续回应的桌面智能伙伴。

灵机一动平台是硬件 AI 应用和智能体创作平台。参赛队可以在平台上完成产品创意梳理、硬件智能体创建、工作流和智能场景配置，并结合知识库、插件生态和垂类模型，将 AI 能力连接到硬件设备。

作品应围绕一个明确、现场可演示的核心场景，形成如下闭环：

> 用户语音或坐姿状态 → 设备采集 → 平台处理 → 智能体判断 → 设备回应 → 用户继续互动

评审重点是场景是否清楚、平台配置是否有效、互动是否顺畅，以及平台与硬件连接是否稳定。

## 3. 参赛任务

### 3.1 确定核心产品场景

说明目标用户、使用时刻、核心问题和产品价值。明确至少两个可运行工作流，并说明每个工作流的触发方式、处理逻辑和硬件反馈。

### 3.2 创建硬件智能体

在灵机一动平台上创建与产品相匹配的硬件智能体，完成角色、任务、交互方式和必要能力的配置。

### 3.3 完成语音交互

设备支持语音唤醒或语音触发，能够完成至少两轮连续对话，并给出与场景相符的回答或动作。

### 3.4 完成摄像头应用

使用 SPI 摄像头进行坐姿识别，可关注头部侧倾、水平转头、身体倾斜和高低肩等姿态特征。

### 3.5 完成情境判断和硬件反馈

至少区分三类使用情况，例如开始、进行中、结束，或聊天、提醒、鼓励、安抚、离席和需要帮助。至少使用两种硬件反馈方式，包括喇叭语音、RGB 灯光、震动提醒或舵机动作。

### 3.6 完成现场演示

现场演示一段稳定、可重复的互动：用户说话或坐姿发生变化，设备完成识别、判断、回应和硬件反馈。演示过程中应能展示至少两个相关工作流。

## 4. 软件平台与现场支持

软件平台和现场支持如下，硬件设备见第七节“参赛设备附页”。

### 4.1 灵机一动平台能力

参赛队可根据作品需要使用以下能力：

1. 硬件智能体：设备创建具备对话、判断和执行能力的智能体。
2. 产品中心：创建和管理硬件 AI 产品，可结合模板快速形成产品方案。
3. 工作流和智能场景：组织多个步骤和能力，形成完整的交互流程。
4. 知识库：为智能体提供指定资料、产品资料或场景知识。
5. 插件生态：按作品需要添加设备控制、天气、闹钟、资源播放、课程管理等插件。
6. 垂类模型：根据具体任务选择和调用适合的模型能力。

### 4.2 现场支持

1. 灵机一动平台账号、开发文档和说明文档。
2. 技术人员现场答疑。
3. 如现场条件允许，提供结构制作支持。

## 5. 评分标准与验收要求

### 基础要求（评分前提）

作品参加基础评分前，应满足以下条件：

1. 支持语音唤醒或语音触发，完成至少两轮连续对话。
2. 使用 SPI 摄像头进行坐姿识别，可关注头部侧倾、水平转头、身体倾斜和高低肩等姿态特征。
3. 至少区分三类使用情况，并使用至少两种硬件反馈方式，包括喇叭语音、RGB 灯光、震动提醒或舵机动作。
4. 使用灵机一动平台创建硬件智能体，完成角色、任务、交互方式及至少一项工作流、智能场景、知识库等平台能力配置，并完成一次实际调用。
5. 现场完成一段可重复的“识别→判断→回应→硬件反馈”端到端互动，并展示至少两个相关工作流。
6. 能够说明语音数据、坐姿识别结果在设备、平台和模型之间的传递、调用关系、返回结果及异常处理方式。

## 6. 交付物

1. **可运行作品**：在提供的 LJWB03 核心板及配套设备上真实运行。
2. **源代码**：可编译运行的完整工程包＋README＋平台配置导出＋第三方组件声明，Tag 标记 `hackathon-final`。
3. **项目海报**：尺寸 0.8 × 1.8 m，用于游园会直观、可视化展示项目的内容。
4. **3 分钟路演或现场演示**：PPT、HTML 文件等可展示文件，用于项目最终路演环节；说明目标用户、核心场景、两个工作流、技术方案、平台配置、能力调用方式和现场效果。
5. **1 页方案说明**：包括目标用户、使用流程、系统架构、灵机一动平台调用方式、智能体配置、视觉和语音处理方法、硬件反馈方式及创新点。
6. **平台配置与调用说明**：提供硬件智能体、角色、工作流、智能场景、知识库、坐姿识别或其他实际使用的平台能力的关键配置截图或导出信息，并标注一次完整调用的触发条件、输入、返回结果和设备反馈。
7. **设备连接和演示说明**：标注使用的摄像头、传感器、RGB 灯带、舵机、震动模块及其作用；说明现场演示的准备步骤和恢复步骤。

## 8. 参赛边界说明

本赛题要求在 48 小时内完成可演示原型，优先保证语音、视觉、平台调用和硬件反馈能够稳定配合。

视觉部分以可复现的坐姿识别为主，可关注头部侧倾、水平转头、身体倾斜和高低肩等姿态特征，不要求高精度人脸识别或复杂视觉测量。

复杂机械结构、多点并行控制，以及其他未列出的传感器和执行器，不作为基础验收条件。作品可以在满足基础闭环后，将其作为创新和加分方向。
