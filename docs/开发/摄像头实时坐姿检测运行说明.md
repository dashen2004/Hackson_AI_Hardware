# 摄像头实时坐姿检测运行说明

更新日期：2026-10-30。

## 当前交付与验证边界

已在工作区接通 BF3901 采集与板端 YOLO11n Pose：真实帧复制、格式转换、独立推理任务、限频、结果保存和串口日志。模型在启动时准备，正常路径在应用初始化结束后启动采集，不要求连接 Wi-Fi 或云平台。已有启动初始化若提前失败退出，则不会走到采集启动点。

用户重插 USB 并确认主板供电后，COM7 恢复通信，已备份原应用并成功烧入实时检测固件。首版复现取流后的堆内存异常；修正 S3 摄像头专用 DMA 分块对齐与 PSRAM 缓存同步后取得完整图像，随后修复 nano printf 不支持 64 位整数格式导致的结果日志崩溃。修正版本构建、应用烧录哈希校验通过；45 秒实测共接收 1230 帧，1226 帧通过格式／完整性检查，产生 12 次推理结果，耗时 2871～3445ms，观察窗口内没有异常重启。检测输出为 `no_person` 或 `unknown`，人体关键点不足，**真人坐姿准确率尚未通过验收**。有效帧和程序持续运行不能代替真人效果验证；也不能以此次短测认定长期稳定。

提供电脑浏览器持续预览和最近检测结果查看，以及按需导出一张缩略图的调试命令。不包含录像、骨架绘制或异常触发马达／灯光。灯圈和马达原有开机测试保留。

## 在浏览器查看画面和检测结果

开发板通过 USB／COM7 连着电脑，固件启用摄像头后，在项目根目录运行：

```powershell
& C:\Users\asus\.espressif\python_env\idf5.4_py3.12_env\Scripts\python.exe tools/camera_preview.py --port COM7
```

保持这个进程运行，在浏览器打开 <http://127.0.0.1:8765/>。页面左侧持续更新摄像头画面，可暂停、旋转、镜像及保存当前 PNG；右侧显示最近检测状态、原因、耗时、帧编号和更新时间。旋转／镜像只改变显示，不改变模型输入；断开 USB 后页面提示连接中断，服务自动重试串口。

服务独占串口，运行时先关闭 `idf.py monitor`、其他串口助手和单张截图脚本；重新烧录前退出此进程以释放串口，控制台按 `Ctrl+C` 停止。HTTP 服务只监听本机 `127.0.0.1`，默认端口 8765，可用 `--http-port` 修改。

这是小尺寸、持续刷新的串口预览：80×106、RGB332 颜色，实际刷新间隔显示在页面；受 115200 波特率限制，清晰度和流畅度不能当作摄像头完整视频输出。预览独立于模型推理：采集任务只在有请求且缓冲空闲时生成小图，独立任务负责输出，忙碌不排队。关闭页面前可暂停预览；服务进程运行且未暂停时会继续请求图像。照片只在内存中更新，点击保存才下载到电脑。

| 接口 | 返回 |
| --- | --- |
| `GET /` | 预览页面 |
| `GET /api/frame.png` | 最新一张预览 PNG；尚无图片时返回 503 |
| `GET /api/state` | 串口连接、预览序号／帧编号／时间、最近坐姿结果／时间、有效帧和丢帧计数 |
| `POST /api/pause`、`POST /api/resume` | 暂停／恢复请求预览，不停止摄像头与 AI |

预览与检测来自各自最近完成的帧，编号可能不同。页面明确显示两者的更新时间；无法判断时先调整取景与光线，不能把旧的检测结果当作当前帧结论。

## 硬件与接线

沿用项目 XJWB03 套件和已识别为 BF3901 的摄像头；完整套件／模组版本仍待确认。摄像头接 3.3V，不接 5V；调整接线先断电。具体方向和照片以[接线说明](../硬件/摄像头/接线说明.md)为准。

| 信号 | GPIO／供电 |
| --- | --- |
| VCC、GND | 3V3、GND |
| SDA、SCL | GPIO21、GPIO47 |
| VSYNC、PCLK、D0 | GPIO4、GPIO13、GPIO8 |
| PWDN | GPIO41 |
| HREF、D1 | 不接 |

GPIO4 与默认舵机配置、GPIO8 与默认 MPU6050 配置冲突；本版保留其初始化关闭状态。不要同时启用冲突外设。

## 数据流和任务配合

1. 开机加载已有 Flash `coco_pose` 分区内的模型，不运行固定 `bus.jpg` 示例；预留 153600 字节 UYVY 副本和 230400 字节 RGB 缓冲。
2. 上电初始化摄像头及两个接收缓冲，在正常应用初始化末尾创建采集任务，由该任务启动 SPI 流。
3. 只接受 240×320、UYVY 格式；帧编号、长度和缓冲边界通过检查后才提交 AI。
4. 采集任务最多每 1000ms 提交一帧。AI 空闲时先取得独占权，复制画面及帧编号／时间，通知推理任务，随后归还摄像头接收缓冲。
5. AI 运行期间跳过新画面，不建立旧画面队列；转换和推理都在独立任务执行。帧副本使用权直到本次处理完成才释放。
6. 结果保存为最新一次完成的结果，并输出一条摘要日志；任务继续接收下一张。

采集任务在 Core 1，优先级 12，内部 RAM 栈 6KiB；AI 任务在 Core 1，优先级 4，内部 RAM 栈 12KiB。图像工作缓冲使用 PSRAM。现有图像转换器和模型对象仅交给一个推理任务使用，不能再从其他任务同时调用这些共享接口。

`camera_pose_get_latest()` 在尚无结果时返回 false；之后返回最近完成的一次结果，包含帧编号、开机后采集时间、处理耗时、错误码和坐姿指标。读取者必须先检查错误码，不能把处理失败当成“无人”。没有历史结果列表。

## 配置与画面方向

位置：`src/firmware/apps/main/qm_config/qm_config.h`。

| 配置 | 本版值 | 含义 |
| --- | --- | --- |
| `CONFIG_QM_POSE_SUPPORT` | 1 | 编译并加载姿态模型 |
| `CONFIG_APP_CAMERA_TEST` | 1 | 编译并启动摄像头 |
| `CONFIG_APP_CAMERA_POSE_INTERVAL_MS` | 1000 | 两次提交的最短间隔，不保证实际每秒一次 |
| `CONFIG_APP_CAMERA_POSE_ROTATE_CW90` | 0 | 原生方向；设为 1 使用现有顺时针 90° 转换器 |

实物安装方向尚未通过照片验证。默认不旋转；若图像实际横置，应按实拍方向调整并重新构建，不能用旋转补偿错误接线。模型每次耗时超过 1 秒时，检测速度会相应降低。

关闭摄像头、保留姿态开关时，仍执行原来的静态图片示例，用于隔离排查。关闭姿态、保留摄像头时，只采集、检查帧和打印诊断日志。

## 构建、烧录和观察

工具链准备见[固件运行说明](固件代码获取与运行说明.md)。在 PowerShell 执行：

```powershell
Set-Location C:\Users\asus\Desktop\Hackson_AI_Hardware\src\firmware
.\dev.bat build
# 确认构建成功、串口可与主控通信后再执行；COM7 按实际设备调整。
.\dev.bat flash -p COM7
```

上述 `flash` 为应用分区烧录，不整片擦除。沿用已烧录模型和分区；首次空板不能只烧应用，完整流程见开发板手册。不要为解决串口不回应而直接擦除配网信息。

串口监视：

```powershell
Set-Location C:\Users\asus\Desktop\Hackson_AI_Hardware
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. .\tools\Enter-Firmware.ps1
idf.py -C src/firmware/apps -p COM7 monitor
```

串口为 115200，退出按 `Ctrl+]`。新固件正常路径应依次出现 `camera pose ready`、BF3901 识别及初始化日志、`stream on`，收到完整帧后才会出现 `camera pose frame=`。部分本机日志格式省略模块标签，请匹配消息正文。

下面是**格式示例，不是本次实测输出**：

```text
camera pose frame=42 captured_ms=8000 status=bad_posture reason=body_tilt processing_ms=900
```

| 字段 | 含义 |
| --- | --- |
| `frame` | 采集帧编号，跳号是跳过帧的正常结果 |
| `captured_ms` | 开机后接收／提交该帧的毫秒数，不是日期时间 |
| `processing_ms` | 格式转换加模型推理的耗时 |
| `status` | `no_person` 无人、`ok` 正常、`bad_posture` 异常、`unknown` 无法判定 |
| `reason` | `none`、`head_tilt`、`body_tilt`、`too_close`、`head_down` |
| `error` | 失败时输出错误码名称，失败日志不输出有效坐姿结论 |

`head_tilt` 对应旧规则中的 `YAW` 枚举。所有指标仍是二维关键点比例，不能当作三维角度或厘米距离。规则只分析第一个人体，阈值尚未真人标定，无跨帧平滑或连续异常持续时间判断。

当前 SDK 启用 `CONFIG_NEWLIB_NANO_FORMAT`，日志中的 `captured_ms` 使用 32 位整数，约 49.7 天回绕；API 结果快照保留完整 64 位时间。不要在此配置下直接用 `%lld`／`PRId64` 后接字符串参数，否则 nano printf 可能错读参数并崩溃。

## 按需查看一张实际画面

固件注册串口命令 `camera_snapshot`，由独占当前帧的推理任务把 RGB 图像按 3 倍降采样导出。默认方向输出 80×106 缩略图，旋转配置输出 106×80；只用于定位方向、取景和颜色问题。115200 串口传输会花数秒，并暂时延后该次推理。

关闭其他串口监视器后，在项目根目录执行（输出目录须已存在，照片保存在仓库外）：

```powershell
& C:\Users\asus\.espressif\python_env\idf5.4_py3.12_env\Scripts\python.exe tools/camera_snapshot.py --port COM7 --output "$env:TEMP\camera-thumbnail.png"
```

脚本只需 `pyserial`，不需要 Pillow，不复位开发板；读取带帧编号和行编号的文本并保存 PNG，不把其他日志写入图片。不完整传输会报错，可再次运行。若没有缩略图，先在串口 `help` 检查命令注册，再检查持续取流和模型任务是否正常。图片属于个人拍摄内容，不纳入 Git。

## 底层接收修正

- 摄像头专用 SPI 驱动的 S3 RX 使用 4032 字节分块，按实际分块数预留 DMA 描述符，使每个 PSRAM 数据起点满足 64 字节对齐；保持其他 SPI 驱动原样。
- S3 RX 通道显式允许访问外部内存；DMA 接收前丢弃旧缓存修改，接收后使 CPU 缓存失效，避免 CPU 读取旧帧或旧脏缓存回写覆盖新帧。
- 去除帧头／行头的原地解码改用 `memmove`，避免源目标重叠时调用 `memcpy` 的未定义行为。
- 修改位于 SDK 中已跟踪的 `managed_components/espressif__esp_cam_sensor` 文件。更新或重新获取组件时须核对补丁，不能仅恢复应用层文件。

## 实物验收与故障排查

- 对准上半身，分别测试离开画面、正常坐直、歪头、身体倾斜、靠近、低头与恢复；记录检测结果是否跟随真人变化。
- 首先确认真实有效帧数量持续增加，再记录处理耗时；长时间没有有效帧时，新版每约 5 秒打印一次诊断提示。
- 检查灯圈、马达原有开机测试和语音功能，持续观察是否重启。当前不能以编译通过推定上述并行功能稳定。
- 若只有初始化成功却没有帧，复核 PCLK、VSYNC、D0 的数据／同步连接和供电；识别芯片成功只验证了控制链路。
- 如果出现重启，保存异常寄存器及回溯，并使用本次匹配的 ELF 解码。可将摄像头开关改为 0 后构建烧录作隔离，但不把关闭功能记作修复。
- 如果 CH343 可见但主控始终无串口数据，核对主板供电、数据连接和主控侧 UART，必要时断电重接。手动下载为按住 BOOT、短按 EN、松开 EN 后松开 BOOT；它不是清除 Wi-Fi 的操作。

## 主要代码

- `apps/main/pose/camera_pose.c/.h`：唯一推理任务、帧副本所有权、限频和结果快照。
- `apps/main/peripheral/bsp_camera.c`：采集、帧验证、提交副本和无帧诊断。
- `apps/main/main.c`：先准备模型，在正常初始化结束后启动采集。
- `apps/main/cloud/ljyd_cloud.c`：移除连云启动摄像头的耦合。
- `apps/main/pose/yolo11_pose.cpp`：继续复用已有转换、模型和判断规则。
- `apps/managed_components/espressif__esp_cam_sensor/src/driver_spi/spi_slave.c`：S3 接收分块与缓存同步修正。
- `tools/camera_snapshot.py`（主仓库）：一次性缩略图读取与 PNG 保存。
- `tools/camera_preview.py`、`camera_preview.html`（主仓库）：本机串口预览服务与浏览器界面。

固件代码由主仓库的 SDK 子模块引用固定，电脑端工具与文档随主仓库管理；子模块协作流程见固件运行说明。
