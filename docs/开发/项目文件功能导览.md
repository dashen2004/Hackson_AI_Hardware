## 如何理解说明的准确范围

- 项目文档和主要应用文件：结合文档索引、源码、头文件、启动入口及 CMake 配置核对用途。
- SDK、第三方依赖和构建目录：完整列出每个文件，但大量说明按所属模块、目录和文件类型归类；清单会标为“目录/类型归类”，不表示逐行审阅了全部第三方实现。
- 文件存在、被编译、启动时被调用、已通过实物验证，是不同状态。下文明确区分，不能把 SDK 自带示例直接当作项目已完成的产品功能。
- 不展开产品密钥、Wi-Fi 密码、凭证或日志正文。文件清单只记录路径和用途。

## 当前实际启动的内容

`app_main()` 调用 QUMIOS 的 `qm_main()`，平台再通过 `qm_application_start()` 启动应用。当前源码调用次序为：

1. 姿态识别示例：加载模型，分析内置 `pose/bus.jpg` 测试图片。
2. 工作队列、板级 IO、语音和资源播放初始化。
3. 云端、物模型控制、课程表和配网初始化。
4. 智能体初始化：云端就绪并收到唤醒后启动会话。
5. 闹钟初始化。

| 功能 | 当前代码状态 | 应如何理解 |
| --- | --- | --- |
| 语音、配网、云连接、智能体 | 有启动调用 | 首次运行记录已记载联网及实际语音回答成功 |
| 资源播放、课程表、闹钟 | 有启动调用 | 有实现，不代表全部业务已通过实物验收 |
| 姿态识别 | `CONFIG_QM_POSE_SUPPORT=1` | 当前入口分析静态测试图；不是实时摄像头坐姿监督 |
| 摄像头 | `CONFIG_APP_CAMERA_TEST=0` | 有驱动源码，当前测试入口关闭 |
| 番茄钟 | `CONFIG_QM_POMODORO_SUPPORT=0` | 有组件源码，当前启动分支关闭 |
| MPU6050 | 驱动在编译列表内，初始化调用被注释 | 不能认定当前正在采集六轴数据 |
| 舵机、震动马达、WS2812 | 驱动在编译列表内，示例启动调用被注释 | 不能认定当前会自动动作、震动或亮灯 |
| 手机使用检测、手机限时、个性化图片屏幕 | 创意文档提出的候选功能 | 本次未在应用启动链中找到完整实现；方案及交付范围待确认 |

上述是源码核对结果。本次没有重新编译、烧录或操作设备；历史实物验证以[开发板首次运行核对记录](开发板首次运行核对记录.md)为准。

## 底层库和生成文件的读法

`esp-idf/` 负责操作系统、外设驱动、Wi-Fi、BLE、TCP/IP、TLS、存储、启动和构建等基础能力；其 `examples/`、`docs/`、测试代码并非当前产品都在运行。`qumios-dev/` 在这些能力上提供统一的云、音频、智能体、事件、任务和设备接口。`components/` 提供音频框架、编解码、声网及服务组件。

| 文件形式 | 一般职责 |
| --- | --- |
| `.c`、`.cpp` | C/C++ 实现；具体属于驱动、业务还是示例，要结合目录判断 |
| `.h`、`.hpp` | 接口声明、数据结构、宏和 C++ 模板等；不一定只有声明 |
| `.S` | 芯片启动或性能优化等汇编代码 |
| `CMakeLists.txt`、`.cmake` | 构建规则和组件依赖 |
| `Kconfig*` | 配置菜单及选项定义 |
| `README*`、`.md`、`.rst` | 模块说明和文档 |
| `LICENSE*`、`COPYING*` | 许可证和版权要求 |
| `.a` | 预编译或构建生成的静态链接库 |
| `.onnx`、`.espdl` | AI 模型资源 |
| `.o`、`.obj`、`.d` | 编译中间对象和依赖记录 |
| `.elf` | 带链接布局、符号等信息的程序，用于调试和后续转换 |
| `.map` | 链接地址、符号与空间占用明细 |
| `vb701n.bin` | 用于烧录的应用镜像 |
| `bootloader.bin` | 引导程序镜像 |
| `partition-table.bin` | 分区表二进制 |
| `flash_args`、`flasher_args.json` | 烧录地址、镜像路径和参数 |
| `build.ninja`、`CMakeCache.txt` | 本机生成的构建任务和配置缓存 |

## 建议的代码阅读顺序

先读 `apps/main/main.c` 看启动链，再读 `qm_config.h` 和 `main/CMakeLists.txt` 确定功能是否启用及参与编译；随后按目标阅读 `voice/`、`agent/`、`cloud/`、`peripheral/` 或 `pose/`。只有需要追踪具体底层行为时，再进入 `qumios-dev/` 和 `esp-idf/`。

主仓库负责团队文档和 SDK 版本引用；SDK 子模块内部修改需要单独提交和共享。`dev.bat` 环境修复与应用启动流程注释已提交到团队 GitHub 仓库的 `codex/firmware-sdk` 分支，产品凭证配置仍仅保留在本机。本导览未改动固件源码或这些配置。
