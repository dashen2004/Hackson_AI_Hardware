## 1. 先看整体：我们到底在开发什么

普通软件开发时，你在电脑上写程序，通常也在电脑或服务器上运行它。这个项目中，你仍在电脑上写代码，但最终运行代码的是开发板上的芯片；它还要直接控制传感器、灯、喇叭等硬件。

```text
电脑端：源代码 + SDK + 项目配置
                 │
                 │ 工具链进行交叉编译、链接、打包
                 ▼
           固件镜像等构建产物
                 │
                 │ 通过 USB / 串口等通道烧录
                 ▼
设备端：Flash 保存固件 → 上电启动 → 主控执行应用
                                      │
                       ┌──────────────┼──────────────┐
                       ▼              ▼              ▼
                  读取传感器      控制灯、声音等     通过网络连接云端
```

这是开发过程的概念图，具体下载通道和外设连接以实际板卡为准。烧录完成后，只要供电和程序配置满足要求，设备通常可以脱离开发电脑运行；依赖云端的功能还需要网络和平台服务。

| 你熟悉的计算机软件开发 | 在本项目中可以怎样理解 | 类比的边界 |
| --- | --- | --- |
| 框架、依赖库、开发工具和示例工程 | SDK 提供芯片与板卡开发所需的基础能力 | SDK 还包含与具体硬件紧密相关的启动、驱动和配置 |
| 构建生成可执行文件或发布包 | 编译生成固件镜像 | 固件面向目标芯片，通常不能直接在 Windows 上运行 |
| 把程序部署到服务器 | 把固件烧录到设备 Flash | 烧录会写入特定存储地址，分区和镜像必须匹配 |
| 程序在操作系统中运行 | 应用与实时操作系统、驱动等一起在芯片上运行 | 不宜直接套用桌面操作系统的进程、文件和权限模型 |
| 调用第三方 API 获取数据 | 通过驱动读取传感器 | 除 API 正确外，还要保证接线、供电和信号时序正确 |
| 查看控制台日志 | 通过串口监视器查看设备日志 | 日志来自设备，需要选对端口和通信参数 |

## 2. 最先掌握的 12 个词

| 术语 / 英文 | 详细解释 | 软件类比 | 本项目例子或注意点 |
| --- | --- | --- | --- |
| 嵌入式系统 / Embedded System | 把计算、存储和控制能力放入特定设备中的系统，通常围绕明确功能工作，资源和功耗也受到约束。 | 为特定用途做的一台小型计算机。 | 主控处理按键、联网和外设控制等任务；最终业务功能待确认。 |
| 开发板 / Development Board、DevKit | 为开发和调试准备的电路板，把主控芯片、电源电路、连接器及部分外设接口放在一起。 | 带好接口、方便实验的“小主机”。 | 手册描述 XJWB03-DevKIT-V1 底板与 LJX40-Audio-KIT-V1 语音模块；实际套件型号待核对。 |
| 主控 / MCU，Microcontroller Unit，微控制器 | 执行程序、管理外设的核心芯片，通常集成 CPU、内存和多种外设控制器。 | 负责运行程序的计算核心。 | 当前工程目标是 ESP32-S3；ESP32-S3 是芯片型号，XJWB03 是板卡相关名称。 |
| SDK / Software Development Kit，软件开发工具包 | 用于开发某平台软件的一组资源，可能包含框架、库、驱动、示例、构建脚本和工具安装入口。不是一个单独的可执行程序。 | 框架 + 依赖 + 示例 + 开发工具的组合。 | `src/firmware/` 是灵机官方 SDK，内含 ESP-IDF 和 QUMIOS 等目录。 |
| 固件 / Firmware | 设备运行的软件，通常保存在断电后仍能保留内容的存储器中。日常也用“固件”指编译好的设备程序镜像。 | 部署到设备上的系统与应用软件。 | 电脑上的源代码要经过构建、烧录后，才能成为板子实际运行的版本。 |
| 工具链 / Toolchain | 把源代码变成目标设备程序所需的工具集合，如编译器、链接器、构建工具和调试器。 | JDK、构建工具等开发环境的组合，但面向特定芯片。 | 本机安装记录包含 Xtensa GCC、CMake、Ninja、GDB 等工具。 |
| 交叉编译 / Cross-compilation | 在一种平台上生成面向另一种平台的程序。 | 在开发机上打包另一种 CPU 架构的程序。 | Windows 电脑上的工具为 ESP32-S3 生成机器码；不是让 ESP32-S3 执行 Windows 的 `.exe`。 |
| 构建 / Build；编译 / Compile | 严格说，编译把源文件转换为目标代码；构建还会组织配置、编译、链接和生成镜像等步骤。日常说“编译一下”往往指完成整个构建。 | 执行项目的 build 命令。 | `dev.bat build` 是构建入口之一；构建通过只能证明电脑端生成了产物。 |
| 烧录 / Flash、Flashing | 使用下载工具，把固件镜像或数据写入设备的非易失存储器。名称中的“烧”不表示正常操作会物理烧坏芯片。 | 向设备部署程序。 | 修改源码后，通常需要重新构建再烧录；仅运行 build 不会更新板子。 |
| 驱动 / Driver | 把上层读写需求转换成硬件寄存器或通信协议操作的软件。 | 第三方服务 SDK 的适配层。 | Windows 的 USB 串口驱动让电脑识别设备；固件里的传感器驱动让主控读取传感器，两者处于不同位置。 |
| 外设 / Peripheral | 相对主控而言，用来输入、输出、通信或存储的硬件。既可指芯片内部的 UART 等控制器，也可指外接的传感器、灯等。 | 程序要交互的输入输出设备。 | MPU6050、摄像头、灯圈、舵机等是资料中涉及的外部模块，不代表已全部接入。 |
| GPIO / General-Purpose Input/Output，通用输入输出 | 可由程序配置用途的数字引脚，能读高低电平、输出高低电平，或复用为其他外设信号。 | 可配置的布尔输入输出接口。 | `GPIO14` 是芯片的信号编号，不一定是连接器上第 14 个物理针脚；也不是任意 GPIO 都能随意使用。 |

## 3. 软件、框架与工程结构

| 术语 / 英文 | 详细解释与软件映射 | 本项目中的含义或使用方式 |
| --- | --- | --- |
| ESP-IDF / Espressif IoT Development Framework | 乐鑫为 ESP 系列芯片提供的开发框架，包含系统、驱动、网络协议支持及配套开发工具。可类比某硬件平台的基础框架。 | 当前 SDK 内置 ESP-IDF 5.4.1；通常先使用这个版本，避免随意换成电脑上另装的版本。 |
| QUMIOS | 当前 SDK 中承载联网、配网、语音、音频等能力的组件层。可以先理解为 ESP-IDF 与业务应用之间的一层通用封装。 | 源码位于 `src/firmware/qumios-dev/`；不应仅凭名称把它当作独立的桌面操作系统。 |
| 应用 / Application、App | 实现产品业务的软件部分。嵌入式应用可能与系统库一起编入固件，而不是运行时安装的独立程序。 | 应用目录是 `apps/`，主要应用入口文件是 `apps/main/main.c`。 |
| 组件 / Component；库 / Library | 可复用的软件模块，封装一组相关功能，供其他代码调用。与常见软件工程中的模块、库相近。 | `components/` 和应用中的组件目录包含不同层次的功能代码。 |
| BSP / Board Support Package，板级支持包 | 针对一块板卡的硬件适配代码与配置，例如引脚分配、外设初始化。它适配的是板卡，而不仅是芯片。 | 阅读 `apps/main/peripheral/` 有助于了解板级外设；这里不意味着项目一定有名为 `bsp/` 的目录。 |
| 宏 / Macro；功能开关 / Feature Flag | C/C++ 预处理阶段可使用 `#define` 和条件编译决定哪些代码参与编译。与运行中修改配置变量的时机不同。 | `apps/main/qm_config/qm_config.h` 管理功能开关；改宏后需按开发说明重新构建并部署。 |
| Kconfig、sdkconfig、menuconfig | Kconfig 描述可配置选项；`sdkconfig` 保存工程选择；`menuconfig` 是配置界面入口。可以类比带类型和依赖约束的构建配置。 | ESP-IDF 还可能用这套机制配置工程，它与 `qm_config.h` 的应用宏属于不同配置入口。 |
| 插件 / Plugin | 一种组织扩展功能的方式，具体加载时机取决于实现。“插件”不一定能在设备运行时下载安装。 | 固件侧插件可由宏决定是否编入固件；平台侧插件则可能是智能体调用的云端能力，需区分。 |
| Git 子模块 / Submodule | 主仓库记录另一个 Git 仓库的特定提交。可类比“锁定外部源码依赖版本”，但它不是普通文件夹复制。 | `src/firmware/` 是子模块；其中的修改需在 SDK 仓库单独管理，主仓库只记录提交引用。 |
| 上游 / Upstream；Fork | 上游是当前代码所来源的仓库；fork 是基于原仓库建立的独立仓库副本，用于维护自己的改动。 | 团队 SDK fork 地址待确认；只在本机改子模块文件，其他成员不会因拉取主仓库自动获得这些改动。 |

## 4. 编译、产物与烧录

| 术语 / 英文 | 详细解释与软件映射 | 本项目中的含义或注意点 |
| --- | --- | --- |
| 编译器 / Compiler；链接器 / Linker | 编译器把源文件转换成目标代码；链接器把多个目标文件、库和符号引用组合成程序，并按内存布局安排内容。 | `undefined reference` 往往属于链接问题，不能只理解为“语法错了”。 |
| CMake、Ninja | CMake 负责描述和生成构建规则；Ninja 按规则执行具体构建。可类比项目构建系统的配置层与执行层。 | 本机工具链已记录这两个工具，日常通常由上层入口调用。 |
| idf.py | ESP-IDF 的工程管理命令入口，组织配置、构建、烧录和日志监视等操作。 | 需使用匹配工程的环境；PowerShell 激活方法见工具链安装记录。 |
| 增量构建 / Incremental Build | 利用之前的中间产物，仅重新处理受变化影响的部分，减少等待。 | 日常 `build` 会复用缓存；具体配置变更若要求重建，应按项目文档操作。 |
| 全量构建 / Rebuild；清理 / Clean | 全量构建重新生成所需产物；清理删除构建缓存或产物。两者发生在电脑上。 | 清理电脑的 `build/` 与擦除设备 Flash 是两个动作。 |
| 固件镜像 / Firmware Image | 按目标设备格式组织的程序或数据文件。这里的 image 是“镜像文件”，不是图片。 | 一个完整烧录流程可能需要应用、bootloader、分区表、模型等多个镜像。 |
| BIN、ELF、MAP | `.bin` 常用于保存待写入的二进制镜像；`.elf` 保存程序结构、符号和可选调试信息；`.map` 展示链接后的内存布局与占用。 | 安装记录列出了 `vb701n.bin`、`vb701n.elf`；名称本身不能证明它要烧到哪个芯片，需看工程目标及烧录配置。 |
| 烧录地址 / Offset；分区表 / Partition Table | 烧录地址指定数据写到 Flash 的哪里；分区表描述各区域的位置、大小和用途。可类比磁盘分区，但具体格式不同。 | 不能把任意 `.bin` 写到任意地址；应用、启动代码、配置与模型区域可能各不相同。 |
| 全量烧录 / flashall；应用烧录 / flash | 这组命令名是本项目脚本的约定：前者按配置写入一组镜像，后者用于应用更新。 | 首次使用、分区改变等情况需按手册处理。全量烧录与“先整片擦除”也不是同义词；是否擦除取决于命令。 |
| 擦除 / Erase | 将某个区域或整片 Flash 恢复到擦除状态。重新写入固件时，也可能只擦除目标写入区域。 | 整片擦除可能清除配网凭据和其他持久化数据；查看命令实际操作范围。 |
| 下载模式 / Download Mode；BOOT | 芯片进入接收新程序的启动模式。BOOT 常是帮助选择启动模式的按键或信号，通常需配合复位时序。 | “下载固件”有时指电脑向芯片写程序，不是从互联网下载。按键操作以本板手册为准。 |
| 烧录包 / Flash Package | 把预编译镜像、地址配置和下载工具等组合成便于分发的包，通常无需接收者重新编译。 | 原手册提到 `demoflashpack/`，但当前获取版本未包含该目录，获取位置待补充。 |

## 5. 芯片、内存与启动

| 术语 / 英文 | 详细解释与软件映射 | 容易误解的地方 |
| --- | --- | --- |
| 芯片 / IC；模组 / Module；开发板 / DevKit | 芯片是集成电路器件；模组把芯片与必要配套电路组合成可复用单元；开发板进一步提供开发连接与调试便利。 | 同一芯片可能出现在不同模组和开发板上；针脚、电源和可用外设不能只按芯片型号推断。 |
| SoC / System on Chip，片上系统 | 在一颗芯片内集成处理器和多种系统功能，例如通信控制器、无线能力等。 | MCU 与 SoC 的叫法可重叠，不必把它们当成严格互斥的分类。 |
| Flash / 闪存 | 断电后内容仍能保留的存储器，用于保存固件、配置或资源。 | 类似持久存储，不等于运行内存。手册标注 16 MB Flash，实际型号和容量需核对。 |
| RAM / Random-Access Memory | 运行时使用的易失性存储器，保存变量、任务栈、缓存等，断电后内容通常丢失。 | Flash 剩余很多，运行时仍可能因为 RAM 不足而崩溃。 |
| SRAM、PSRAM | SRAM 常用于芯片内部工作内存；PSRAM 常用来扩展可用运行内存，容量、速度和访问限制取决于硬件。 | 摄像头帧或音频缓冲可能占用较多内存；本项目实际 PSRAM 容量与配置需核对，不能由 Flash 容量推出。 |
| ROM / Read-Only Memory | 通常指芯片制造时就固化的代码存储区域，可包含最早期启动或下载相关程序。 | 它与后来烧入 Flash 的应用固件不是同一层。 |
| Bootloader / 引导程序 | 应用运行前的启动代码，按启动配置选择和加载应用，可能参与升级与校验。 | 可类比电脑启动链的一部分；它不是业务主循环。 |
| 上电 / Power-on；复位 / Reset；重启 / Reboot | 上电是获得供电；复位让相关硬件或软件状态回到规定起点；重启是重新开始运行系统。实际范围取决于实现。 | 按 RESET 通常不会擦掉 Flash；“配网复位”“恢复出厂设置”则可能主动清除某些持久数据。 |
| NVS / Non-Volatile Storage；KV | NVS 是非易失存储服务；KV 是键值形式的数据组织方式。可类比设备本地的持久化配置库。 | 当前文档描述配网凭据、音量、闹钟等可保存在这类区域；重新烧应用不一定清掉它们。 |
| OTA / Over-the-Air Update，空中升级 | 通过网络等无线通道获取和安装新固件。双应用分区常用于下载新版本后切换启动。 | 双分区是存储布局；完整升级、校验和回滚是否可用，还要看固件与平台实现，不能只看分区名。 |

## 6. 接线、供电与电气概念

这一节的类比只帮助理解术语，不能作为接线表。实际操作前，核对模块型号、板卡引脚定义、供电电压、信号电平和方向。

| 术语 / 常见标记 | 详细解释与软件映射 | 接线时应该怎样理解 |
| --- | --- | --- |
| 引脚 / Pin；排针 / Header；丝印 | 引脚是器件连接点；排针是一组连接针；丝印是电路板上印出的名称和标记。 | 芯片 GPIO 编号、芯片封装脚号、排针位置是不同编号体系；要查对应关系。 |
| VCC、VDD、VIN、3V3、5V | 常见电源网络或电源引脚名称。3V3 通常表示 3.3 V；VIN 常表示某电源输入，但最终以电路设计为准。 | “写着 VCC”不等于“随便接 5 V”；接口名称本身不能确定允许电压。 |
| GND / Ground，地；共地 / Common Ground | GND 是电压的参考节点；共地是让相互通信的电路共享参考。 | 非隔离的常见模块连接通常需要共地；只连信号线而没有合适参考可能无法可靠通信。 |
| 电压 / Voltage，V | 两点之间的电势差。供电电压描述供电条件；逻辑电平描述信号的电压范围。 | 一个模块支持 5 V 供电，不代表它的全部信号都能直接与 5 V 逻辑连接。 |
| 电流 / Current，A、mA；功率 / Power，W | 电流描述电荷流动；电源容量表示其可供给能力。直流下常用 `P = U × I` 估算功率。 | 在电压等条件匹配时，电源额定电流更大通常不意味着强行灌入同样大的电流；负载仍需在规格内使用。 |
| 高低电平 / HIGH、LOW；逻辑 1 / 0 | 数字电路用规定范围的电压表示 1 和 0，而非要求恰好等于某个理想电压。 | “输出 1”不是输出 1 V；输入阈值和最大允许电压要查手册。 |
| 3.3 V / 5 V 电平；电平转换 / Level Shifting | 不同逻辑电压域之间可能需要转换，保证能识别且不超过输入允许范围。 | 不应默认 ESP32-S3 的普通 GPIO 可以承受 5 V 输入。 |
| 上拉 / Pull-up；下拉 / Pull-down；悬空 / Floating | 用电阻把未被主动驱动的信号保持在默认高或低电平；悬空表示缺少可靠的确定状态。 | 类似给输入设置默认值，但这是电路行为；内部上拉与外部上拉的能力也不同。 |
| 开漏 / Open-drain；推挽 / Push-pull | 开漏输出通常只主动拉低，靠上拉变高；推挽输出可主动驱动高和低。 | I²C 常使用开漏与上拉；不能让两个推挽输出随意互接并输出相反电平。 |
| 低电平有效 / Active-low；上升沿、下降沿 / Edge | 低电平有效指信号为低时表示被触发；上升沿与下降沿分别是低到高、高到低的变化。 | 名称中的 `_N`、`#` 常提示低有效，具体仍看定义；“读到 0”也可能表示按键正被按下。 |
| 短路 / Short Circuit；过流 / Overcurrent；压降 | 短路是非预期的低阻通路；过流是电流超过允许范围；压降是电流流过线路等阻抗产生的电压降低。 | 外设启动可能使电源电压下降；反复重启可能来自供电问题，不能只查软件。 |
| 原理图 / Schematic；PCB / Printed Circuit Board；数据手册 / Datasheet | 原理图描述电气连接；PCB 图描述板上布局与走线；数据手册说明器件规格、引脚和使用条件。 | 原理图用于查“接到哪里”，PCB 和实物图用于查“实际在哪里”，数据手册用于查“允许怎样接”。 |
| FPC、FFC、连接器触点方向 | FPC 常指柔性印制电路，FFC 指柔性扁平线缆。连接器接触面与线缆方向必须匹配。 | 摄像头排线看起来能插入，也可能方向错误；应结合项目摄像头接线说明和实物图确认。 |

<a id="interfaces"></a>

## 7. 外设通信接口

“接口”既可能指软件 API，也可能指电气信号、通信协议或连接器形状。看到“支持 USB / UART / SPI”时，需要继续确认它说的是哪一层。

| 术语 / 常见信号 | 详细解释与软件映射 | 本项目中的例子或边界 |
| --- | --- | --- |
| 总线 / Bus；协议 / Protocol | 总线是设备传输信息的一组共享连接与规则；协议定义如何组织和解释通信。可类比网络传输通道及消息约定。 | 插头能插上，只能证明机械形状匹配，不能证明供电、引脚和协议匹配。 |
| UART / Universal Asynchronous Receiver/Transmitter | 异步串行收发接口，双方按约定速率发送字节，常见信号是 TX、RX 和 GND。它本身不规定业务消息格式。 | 主控与 VB701N 的音频链路，以及日志接口都涉及 UART，但它们不是同一条通道。 |
| TX、RX；流控 / Flow Control | TX 表示发送，RX 表示接收，相对于信号所属设备命名。流控用来协调发送速度，避免接收端来不及处理。 | 常见 UART 是一侧 TX 连另一侧 RX；本项目音频链路还涉及流控，不能只看两根数据线。 |
| 串口 / Serial Port；COMx | 串口是串行通信接口的常见称呼；Windows 用 `COM3` 等名字表示可打开的串行端口。 | `COMx` 是占位符，应替换为电脑实际识别的端口；它不是板子的固定型号。 |
| USB、USB 转串口、TTL 串口、RS-232 | USB 是独立的总线标准；USB 转串口桥把 USB 通信转换成串行信号；TTL 电平串口与 RS-232 电气规格不同。 | 不能因都叫“串口”就直接混接。板上 USB 是原生接口还是桥接接口，需查板卡设计；供电线也未必支持数据。 |
| 波特率 / Baud Rate；115200 8N1 | 波特率描述符号传输速率；8N1 表示 8 个数据位、无校验、1 个停止位。在常见 UART 条件下 115200 可近似理解为每秒 115200 个线路比特。 | 这不是每秒 115200 字节；计入起始位和停止位，理论数据速率约为 11520 字节/秒。手册日志参数是 115200 8N1。 |
| I²C / I2C / Inter-Integrated Circuit；SDA、SCL | 常见两线同步总线：SDA 是数据线，SCL 是时钟线。控制器通过设备地址选择目标，再按协议读写。 | MPU6050 使用 I²C；同一总线上可连接多个设备，但地址、电平、上拉和负载等必须满足要求。 |
| I²C 设备地址 / Device Address；ACK / NACK | 设备地址标识总线上的某个目标；ACK / NACK 是接收方对传输的应答。常见文档有 7 位地址与包含读写位的表示差异。 | “扫描不到地址”先检查供电、连线和地址条件；不要把设备地址与寄存器地址混为一谈。 |
| 寄存器 / Register；位字段 / Bit Field | 外设常把配置与状态组织为可读写的寄存器，每个地址中的若干位具有特定含义。可类比硬件暴露的配置和状态字段。 | 对 MPU6050 而言，先选 I²C 设备，再访问内部寄存器；`WHO_AM_I` 是身份识别寄存器，不是总线地址。 |
| SPI / Serial Peripheral Interface；SCLK、MOSI、MISO、CS | 同步串行接口，常见时钟、控制器发送、控制器接收和片选信号。也存在信号合并等变体。 | 赛题提到 SPI 摄像头；实际信号和读写流程以模组、转接板与驱动为准，不能套用任意四线示意图。 |
| 片选 / CS，Chip Select | 用于选择参与当前通信的目标设备，常见于 SPI。多个目标可共用部分总线信号，但分别使用片选。 | CS 有效电平及切换时机属于协议要求，不是只在初始化时随便设一次。 |
| I²S / I2S / Inter-IC Sound | 用于数字音频数据传输的串行接口，常涉及时钟、声道选择和数据线。 | I²S 与 I²C 只差一个字母，用途和时序差别很大；手册描述主控到 VB701N 是 UART，不能擅自改按 I²S 接线。 |
| PWM / Pulse-Width Modulation；频率、周期、占空比 | 通过周期性高低电平控制输出。周期 `T = 1/f`，占空比为高电平持续时间除以周期。 | 可用于调光或某些执行器控制；舵机更要关注脉宽和周期，WS2812 则使用专门的数字数据时序。 |
| ADC / Analog-to-Digital Converter；DAC / Digital-to-Analog Converter | ADC 把模拟电压转换成数字数值；DAC 把数字值转换成模拟输出。可类比连续量与离散数值之间的转换。 | 并非每个 GPIO 都支持这些功能；PWM 也不自动等于真正的 DAC。 |

<a id="runtime-debug"></a>

## 8. 实时系统与调试

| 术语 / 英文 | 详细解释与软件映射 | 调试时的实际意义 |
| --- | --- | --- |
| RTOS / Real-Time Operating System；FreeRTOS | 实时操作系统为任务调度、同步和定时等提供能力。实时强调在所需时限内响应，不等于任何代码都会自动更快。 | ESP-IDF 使用 FreeRTOS；应用可能同时存在联网、音频、传感器等任务。 |
| 任务 / Task；调度 / Scheduling；优先级 / Priority | 任务是可被调度的执行单元，可先类比线程。调度器结合优先级、阻塞状态和处理器资源分配运行机会。 | 高优先级任务长时间占用 CPU，可能让其他工作无法及时执行；任务通常不能直接当成独立进程理解。 |
| 中断 / Interrupt；ISR / Interrupt Service Routine | 硬件事件可以触发 CPU 执行中断处理程序，例如引脚变化或数据到达。可类比事件回调，但执行环境限制更严格。 | 中断中通常应快速处理或通知任务；不能随意执行阻塞、长耗时操作，API 也需适用于 ISR。 |
| 轮询 / Polling；阻塞 / Blocking；忙等 / Busy-wait | 轮询是反复检查状态；阻塞让任务等待条件并把运行机会交出；忙等持续占用 CPU 检查或延时。 | “等 1 秒”可能有不同实现，忙等与任务延时对其他任务的影响不同。 |
| 队列 / Queue；信号量 / Semaphore；互斥锁 / Mutex | 用于任务或中断之间传递数据、通知事件和保护共享资源。与常见并发编程概念相通。 | 例如采集任务把读数放入队列，业务任务消费；共享总线或音频资源可能需要同步。 |
| 看门狗 / WDT，Watchdog Timer | 监测程序或系统是否在规定时间内正常推进，超时后可触发告警、异常处理或复位。 | 反复重启可能来自任务卡住，也可能是中断被长期阻塞；只延长超时时间未必能解决根因。 |
| 栈 / Stack；堆 / Heap；内存泄漏 | 栈保存调用现场和局部变量等；堆用于动态分配；未正确释放资源会造成泄漏。 | 某个任务栈溢出，与整个系统堆空间不足是不同问题；即使 C 代码能编译，也可能在运行中越界。 |
| DMA / Direct Memory Access；FIFO / First In, First Out | DMA 让外设与内存传输数据时减少 CPU 搬运；FIFO 是按先进先出方式缓冲数据的机制。 | 音视频等连续数据流常涉及缓冲、容量与读写速率，数据来不及处理可能被丢弃。 |
| 串口监视器 / Serial Monitor；CLI / Command-Line Interface | 监视器在电脑端打开串口显示设备输出；CLI 让用户输入设备支持的命令。与终端体验类似，但目标是开发板。 | 当前手册描述 UART0 用于日志与命令；烧录时可能需要关闭占用同一端口的监视器。 |
| 日志级别 / Log Level；Tag | 常见 E / W / I / D 表示错误、警告、信息、调试；Tag 标识输出模块。 | 先看哪个模块、在哪一步失败。W 不一定导致失败，I 也不等于对应硬件功能已验证。 |
| Panic、异常 / Exception、Backtrace | Panic 常表示无法继续的严重错误；backtrace 是调用栈回溯，帮助定位崩溃位置。 | 将地址解析到源码通常需要与板上固件匹配的 ELF；保留完整日志比只保留最后一行更有用。 |
| Brownout / 欠压检测 | 供电下降到阈值附近时，芯片检测到异常并可能复位，以避免不可靠运行。 | 电机或无线发射的瞬时负载可能暴露电源问题；它与单纯的程序崩溃不是同一个原因。 |
| JTAG、GDB、OpenOCD | JTAG 是常见硬件调试接口；GDB 是调试器；OpenOCD 可连接调试硬件与调试器，实现暂停、断点和内存查看等。 | 串口打印不等于断点调试；工具已安装也不意味着调试线路和配置已验证。 |

## 9. 联网、平台与设备身份

| 术语 / 英文 | 详细解释与软件映射 | 本项目中的含义或边界 |
| --- | --- | --- |
| Wi-Fi、SSID、2.4 GHz / 5 GHz | Wi-Fi 是无线局域网技术；SSID 是无线网络名称；2.4 GHz 和 5 GHz 是不同工作频段。 | 当前开发板手册要求使用 2.4 GHz Wi-Fi；不要把手机已连上某热点当作板子一定支持它的证明。 |

| 配网 / Provisioning | 给设备配置接入网络所需的信息，常见是 Wi-Fi 名称和密码。 | 类似给新部署的服务配置网络环境；配网成功后，设备还需成功连接平台。 |
| 绑定 / Binding | 在平台中建立设备与账号、产品或智能体之间的关联，具体关系取决于平台。 | 已连接 Wi-Fi、不代表已经绑定正确账号或智能体；不同阶段要分别确认。 |
| PID / Product ID | 在当前平台语境中表示产品标识，用来说明设备属于哪个产品。 | 这里不是进程 ID，也不是控制算法中的 PID；它也不能单独代表某一台实物设备。 |
| SECRET / 密钥；设备身份凭据 / Credentials | 用于注册、认证或证明身份的数据。产品级密钥与单设备凭据可能处于不同阶段、具有不同用途。 | 从平台获取实际配置，按文档使用；不要把示例值当成团队已配置值，也不要把真实密钥提交到仓库。 |
| 动态注册 / Dynamic Registration；dynreg | 设备通过平台规定的身份信息完成注册，获取或建立后续接入所需的设备身份。 | 可类比客户端首次注册领取凭据；日志停在这里时，优先核对产品配置、认证信息与平台环境。 |
| 测试环境 / 正式环境 | 独立的服务、产品和凭据体系，概念与后端开发中的测试服、生产服相近。 | PID、密钥与服务环境需要匹配，不能跨环境随意混用。 |
| MQTT / Message Queuing Telemetry Transport | 常见物联网消息协议，客户端通过 broker 按 topic 发布和订阅消息。可类比消息代理中的发布订阅模式。 | 当前 SDK 文档描述 MQTT 云端接入；看到 MQTT 已连接，也仍需确认业务消息是否正确处理。 |
| 物模型 / Thing Model；属性、事件、方法 | 平台用结构化定义描述设备状态、上报消息与可调用动作。可类比设备的 API schema。 | “音量是多少”可抽象为属性，“检测到动作”可抽象为事件，“设置音量”可抽象为方法；具体字段以平台定义为准。 |
| 心跳 / Heartbeat；重连 / Reconnect | 心跳帮助判断连接是否仍有效；重连是在连接中断后恢复通信。 | “曾经在线”不等于始终在线；业务调用还要考虑断网和重新认证等情况。 |
| TLS / Transport Layer Security；证书 / Certificate | TLS 保护传输并支持身份认证；证书可用于证明身份或验证通信对端。 | 证书、密钥、产品 ID 是不同对象；认证失败不一定是 Wi-Fi 信号问题。 |

## 10. AI、音频、摄像头与执行器

以下术语覆盖当前赛题和已有硬件资料，帮助读懂文档，不代表所有功能都已选定或实现。

| 术语 / 英文 | 详细解释与软件映射 | 本项目中的例子或常见误解 |
| --- | --- | --- |
| Agent / 智能体；LLM / Large Language Model | LLM 是处理和生成语言的大模型；智能体通常结合模型、指令、上下文及工具来完成任务，具体能力取决于平台实现。 | 设备侧程序负责连接、采集和执行等工作，平台侧 Agent 负责哪些决策需按方案确认；不能把 Agent 等同于板上运行的大模型。 |
| 端侧 / On-device；云端 / Cloud | 端侧表示在设备本地执行，云端表示在远程服务执行。两者对延迟、联网和资源的要求不同。 | “设备有 AI 功能”不一定表示所有模型都在 ESP32-S3 上运行；每项能力的执行位置需分别确认。 |
| 训练 / Training；推理 / Inference；模型 / Model | 训练根据数据调整参数；推理用已有模型计算输出；模型文件可能包含网络结构和权重等数据。 | “模型分区”保存模型资源，并不等于设备正在训练模型，也不一定是语言模型。 |
| 唤醒词 / Wake Word；VAD / Voice Activity Detection | 唤醒词检测特定呼叫词，VAD 判断是否存在语音活动。 | 能听到唤醒提示不代表语音识别、联网和回复播放整条链路都正常。 |
| ASR / Automatic Speech Recognition | 把语音转换成文字，即语音识别。 | 对话链路中“听懂说了哪些字”的一环；不等于理解意图或决定动作。 |
| TTS / Text-to-Speech | 把文字转换成语音，即语音合成。 | 日志出现 TTS 完成，不代表扬声器一定已经发声，音量和播放通路仍需验证。 |
| 采样率 / Sample Rate；位深 / Bit Depth；声道 / Channel | 采样率是每秒采样次数；位深描述每个样本的表示精度；声道表示独立声音通道数量。 | 手册音频描述包含 16 kHz、单声道；16 kHz 不是每秒 16 KB，也不是 CPU 主频。 |
| PCM、Codec、Opus、音频帧 | PCM 是常见原始采样表示；codec 负责音频编码解码；Opus 是音频编码格式之一；音频帧通常承载一小段时间的数据。 | 手册描述 Opus、16 kHz、单声道、20 ms 音频帧。采样率、帧时长与压缩后的数据字节数不是同一个量。 |
| 分辨率 / Resolution；帧率 / FPS | 分辨率表示一帧图像的像素尺寸；帧率表示每秒采集、传输或处理的帧数。 | 更高分辨率往往消耗更多内存和带宽，未必带来更高识别速度；采集帧率与推理帧率也可能不同。 |
| 姿态估计 / Pose Estimation；关键点 / Keypoint | 从图像估计身体等对象的位置或姿态，关键点是鼻子、肩部等特征位置的数值表示。 | 赛题涉及坐姿识别；从关键点判断“坐姿不好”还需要业务规则或模型，阈值和方案待确认。 |
| IMU / Inertial Measurement Unit；MPU6050；六轴 | IMU 是惯性测量单元；MPU6050 提供三轴加速度与三轴角速度测量，合称六轴。 | 它不是摄像头；读出原始数据不等于直接得到稳定姿态角，也不等于获得人体坐姿。 |
| 加速度计 / Accelerometer；陀螺仪 / Gyroscope；标定 | 加速度计测量比力，静置时读数也受重力相关效应影响；陀螺仪测角速度；标定用于估计零偏、比例等误差。 | 将它们用于倾角、运动状态等判断时，要考虑安装方向、单位、误差与数据融合。 |
| 舵机 / Servo；位置型、连续旋转型 | 带控制能力的执行器。位置型通常根据控制脉冲转到目标位置；连续旋转型通常控制方向和速度。 | 不能把所有舵机都写成“输入角度就能转到那里”；先确认实际型号、脉宽范围和供电。 |
| WS2812 / 可寻址 RGB 灯珠；级联 / Cascade | 内含控制逻辑的灯珠，按规定数字时序接收各灯颜色数据，多颗可依次传递数据。 | 它通常用专门驱动发送数据，不是用普通 PWM 占空比直接设置 RGB；灯圈供电需求还与亮灯数量和亮度有关。 |
| 震动马达 / Vibration Motor；MOSFET / MOS 管；驱动电路 | 马达通过机械运动产生震动；MOSFET 可作为电控开关，由弱控制信号控制较大的负载电流。 | GPIO 控制信号与给电机供电是两件事；不要默认 GPIO 能直接驱动电机，模块电路和额定电流需核对。 |

## 11. 把术语放进一次完整开发流程

假设我们要增加“检测到某个动作时亮灯”的功能。这里只说明开发方法，传感器、灯的型号、引脚、协议和触发条件都需要另行确认。

| 阶段 | 实际在做什么 | 对应术语 | 什么结果才算这个阶段完成 |
| --- | --- | --- | --- |
| 1. 确认硬件 | 查传感器与灯的型号、接口、允许供电和引脚占用。 | 开发板、外设、数据手册、GPIO、逻辑电平。 | 有明确硬件清单和接线依据，不只是“看起来插得上”。 |
| 2. 找软件入口 | 找采集驱动、业务入口和功能开关，先看已有能力能否复用。 | SDK、驱动、组件、宏、应用。 | 知道改哪个模块，以及是否需要新增驱动或配置。 |
| 3. 写业务逻辑 | 读取数据，判断条件，再调用灯的控制接口；合理安排执行和等待。 | 寄存器、任务、队列、阈值、外设协议。 | 代码表达了预期行为，并处理必要的错误和资源约束。 |
| 4. 在电脑上构建 | 使用匹配的工具链和目标配置生成镜像，检查错误与大小。 | 交叉编译、链接、BIN、ELF、分区。 | 构建成功并生成产物；这时还不能宣称板子能正常运行。 |
| 5. 部署到设备 | 选择实际下载端口，按工程要求烧录对应镜像，再让设备启动。 | COM、下载模式、烧录、bootloader、复位。 | 下载工具报告写入成功；还需要后续启动与功能检查。 |
| 6. 验证设备行为 | 看启动日志与传感器数据，触发动作，观察灯是否按预期响应。 | 串口监视器、日志、运行时错误。 | 设备行为符合预期，出现异常时能留存日志和复现步骤。 |
| 7. 如需云端再验证 | 分别检查配网、设备身份、平台绑定、消息接收与动作执行。 | BLE、Wi-Fi、PID、MQTT、物模型、Agent。 | 对应云端交互可复现，不能只以“设备在线”代替完整业务验证。 |
| 8. 留下可复现记录 | 记录代码版本、型号、接线、供电、配置和操作步骤。 | SDK 版本、子模块引用、验证记录。 | 其他成员按记录也能复现，未测项目明确标出。 |

结合当前仓库状态阅读时，要区分历史记录与本次操作：[Windows 工具链安装记录](Windows工具链安装记录.md)记载电脑端已完成构建验证，但尚未进行硬件烧录和实物验证。本文只是术语整理，没有重新构建或验证板卡。

## 12. 常见说法翻译与容易混淆的概念

### 12.1 听到这句话时，实际在说什么

| 常见说法 | 翻译成更熟悉的软件语言 | 接下来应该确认什么 |
| --- | --- | --- |
| “先把 SDK 拉下来。” | 获取完整开发工程及它锁定的源码依赖。 | 子模块是否初始化、版本是否匹配，而不是目录是否存在就算完成。 |
| “把环境激活一下。” | 让当前终端使用工程需要的 Python、编译器与工具路径。 | 当前窗口的版本与路径是否正确；它不是给设备开机。 |
| “改完宏重新编一下。” | 修改构建时的功能选择，生成包含相应代码的新版本。 | 是否按要求重建，是否把新固件部署到设备。 |
| “固件刷进去了吗？” | 构建产物是否已写入目标设备。 | 写的是哪块设备、哪些分区、哪个版本，是否有成功日志。 |
| “串口打一下日志。” | 输出设备状态，并在电脑上读取。 | 日志 UART、COM 端口、波特率与地参考是否正确。 |
| “I²C 扫不到设备。” | 总线探测没有收到预期地址的应答。 | 供电、SDA / SCL、共地、上拉、地址和模式；它不直接证明传感器损坏。 |
| “GPIO 拉高 / 拉低。” | 配置输出并驱动到逻辑 1 / 0 对应的电平。 | 引脚是否允许这样驱动、有没有连接到其他输出、负载能力是否满足。 |
| “喂狗没喂上。” | 系统未在规定时间内完成看门狗要求的服务或进度检查。 | 是否死循环、长时间忙等或阻塞关键任务，以及具体是哪类看门狗。 |
| “设备在线但没反应。” | 网络连接成立，但业务链路还存在其他未完成环节。 | Agent 或产品关联、消息内容、订阅处理、任务状态和执行器链路。 |
| “把板子复位一下。” | 重新开始执行启动流程。 | 对方指普通 RESET、配网复位还是清除持久配置，这几种操作不同。 |

### 12.2 几组不能直接画等号的概念

| 容易混淆的一组词 | 区别 |
| --- | --- |
| SDK / 固件 / 固件镜像 | SDK 是开发资源；固件是设备软件；固件镜像是可用于存储或部署的具体产物。 |
| 获取代码 / 安装工具 / 构建 / 烧录 / 运行验证 | 分别证明代码在本地、工具可用、产物可生成、产物已写入、设备行为正确。前一步成功不能替代后一步证据。 |
| 构建成功 / 硬件可用 | 构建不检查真实接线、供电、凭据或运行时业务行为。 |
| Flash / RAM | 前者主要用于断电保存，后者主要用于运行中工作；两者容量与不足问题分别排查。 |
| GPIO 编号 / 排针序号 | GPIO 是芯片信号编号，排针序号是连接器位置；必须依据板卡映射。 |
| USB 接口 / UART 日志口 | USB 描述一类总线与连接；UART 描述另一类串行接口，二者可能通过桥接关联，也可能是独立路径。 |
| I²C / I²S / SPI | 分别是不同接口，线数、信号含义、时序与用途不同；不能只按相似名字或线色连接。 |
| I²C 地址 / 寄存器地址 | 前者选总线上的设备，后者选该设备内部要访问的字段。 |
| PWM 占空比 / 舵机角度 | 舵机响应取决于具体协议、周期和脉宽；改变周期后，同一占空比不一定代表同一脉宽。 |
| 供电电压 / 信号电平 | 电源接口允许某电压，不代表通信输入也允许该电压。 |
| 全量烧录 / 整片擦除 / 恢复出厂 | 全量烧录写一组镜像；整片擦除清除整个 Flash；恢复出厂通常由软件定义重置哪些配置，操作范围不同。 |
| 配网成功 / 连云成功 / 绑定成功 / 业务成功 | 网络接入、平台认证、关联关系和实际功能分别属于不同阶段。 |
| 固件插件 / 平台插件 | 前者可能编译进板上程序，后者可能运行在云端；修改位置和部署方式不同。 |
| 姿态模型 / LLM | 姿态模型可以处理图像关键点等视觉任务；大语言模型主要处理语言相关任务，不能因都叫模型就混为一谈。 |
