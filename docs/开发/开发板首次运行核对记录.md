## 串口与首次烧录

- 在用户连接主控板后，通过 Windows 串口列表与即插即用设备列表确认 COM7，未发现该设备的驱动异常。
- 最初以 115200 波特率被动读取约 6 秒收到 0 字节；随后通过串口控制线复位，已捕获启动日志。短时间没有日志不能据此判断固件未运行。
- esptool 实测芯片为 ESP32-S3 QFN56 rev 0.2，Flash 为 16 MB；启动日志显示 PSRAM 为 8 MB。
- 用户配置凭证后，本机检查 PID 为 11776、密钥为 32 个 ASCII 字符，无空白或遮罩字符，并确认新凭证已进入编译产物。此检查仅验证配置格式与构建结果，不代表云端鉴权成功；不记录密钥值。
- 在项目根目录执行 `.\src\firmware\dev.bat build` 成功，再执行 `.\src\firmware\dev.bat flashall -p COM7`，全部 6 个镜像烧录并通过哈希校验。没有执行整片擦除；烧录工具仅擦除写入镜像涉及的区域。
- 镜像地址：引导程序 `0x0`、分区表 `0x10000`、OTA 初始数据 `0x1d000`、PHY 初始数据 `0x1f000`、应用 `0x20000`、姿态模型 `0x810000`。
- 启动观察期间没有发现崩溃重启，音频引擎初始化成功，BLE 配网启动返回 0。设备没有已保存的 Wi-Fi 配置，尚未完成联网与云连接。

## 音频实测与排查

- 最终原因：用户确认麦克风与喇叭插头接反，纠正后已听到声音。此前关于启动时序的推测未被证实为此次无声原因。接线应按语音板实际 `MIC` / `SPK` 标识核对，不能只按插头外形判断。
- 按用户要求，已撤回此次排查新增的设备就绪等待及开机音超时调整。`qm_audio_device_vb701n.c` 和 `boot_sound.c` 已恢复为当前 SDK 提交的原始内容；保留本机产品凭证和此前的 `dev.bat` 环境修复。以下时序调整记录仅用于说明排查经过，不代表当前代码。
- 回退后执行 `dev.bat build` 成功，应用大小恢复为 `0x2f8f70`（3,116,912 字节），随后执行 `dev.bat flash -p COM7` 完成应用烧录、哈希校验及自动重启。两份音频源码与 SDK HEAD 差异为零；SDK 工作区只保留产品凭证和 `dev.bat` 的既有修改。用户确认的发声结果来自纠正插头后、回退烧录前；回退后的实际听音尚未单独确认。
- 用户在一次明确留意声音的重启测试中确认“完全没有声音”，并确认语音模块排线和配套喇叭均已接好。
- 音频串口为 UART1，主控 TX=GPIO40、RX=GPIO39，波特率 2000000，流控输入 GPIO38。VB701N 返回版本 `1.1.7`，并持续返回麦克风 PCM 数据；这证明双向串口通信及音频数据上行在工作，尚未验证人声内容或识别准确性。
- 日志中的音量配置为 80，对应芯片档位 24/31。
- 原始时序中，约在应用计时 3.13 秒开始发送开机音，直到约 4.15 秒才完成版本握手后的等待并设置硬件音量。这是需要验证的无声原因之一。
- 本地修改 `qumios-dev/platform/mcu/esp32s3/qm_audio/qm_audio_device_vb701n.c`：播放开始前等待初始化流程发送音量与录音启动命令，最多等待 20 秒，并保留停止/中断检查。
- 第一版时序修正已编译并完成应用烧录、哈希校验，用户确认仍然无声。串口显示播放在 3.135 秒等待就绪，但开机音发送队列在 4.137 秒触发原有 1 秒超时（`ret=-2 frames=63/86`），早于 4.159 秒完成初始化；该版本不能用于判断等待就绪后的实际播放效果。
- 配套调整 `apps/main/voice/boot_sound.c` 的队列写入和播放完成等待上限至 25 秒，覆盖设备层最长 20 秒启动等待。代价是在音频模块异常时，提示音任务可能更晚报告超时；正常就绪时不会固定等待 25 秒。
- 配套调整版编译成功。应用烧录写入完成后，工具在最终校验阶段报 `Packet content transfer stopped`；随后使用 esptool、115200 波特率独立执行 `verify_flash 0x20000 src/firmware/apps/build/vb701n.bin`，返回 `verify OK (digest matched)`，确认 Flash 应用与新产物一致。应用大小为 `0x2f9090`（3,117,200 字节），分区剩余约 25%。
- 新版重启日志：3.139 秒等待就绪，4.151 秒发送硬件音量 24，4.155 秒完成录音启动流程，4.159 秒首次发送扬声器帧，4.256 秒开始 Opus 解码后的 PCM，5.473 秒完成本地播放流程（`ret=-6 frames=86/86`）。原有 1 秒队列超时未再出现。随后引导用户拔插 USB 断电重启，用户仍反馈没有声音；启动时序修正没有解决实际无声问题。
- 当时的串口日志只能确认主控已将扬声器帧写入 UART，不能单凭日志确认实际发声；最终通过用户纠正接线后的听音结果确认恢复。
- 用户补充整体实物照片：USB 接在主控板上，主控与语音板通过黑色连接件相连；图中喇叭的较粗红黑线接在语音板照片右侧白色接口，另一根细红黑绞线接在照片左侧白色接口。用户明确说明细绞线连接麦克风，后续确认两者插反并已纠正。此前仅凭模糊图片判断某接口为电池接口的说法已撤回，不作为接线依据。
- 开机音日志 `local play done ret=-6` 对应 `-QM_ENOSYS`。当前 VB701N 适配层未声明物理播放完成确认（DRAIN）能力，引擎因此返回“不支持”。该错误不能单独证明 PCM 未发送或喇叭硬件故障；未将“串口写完”等同于“扬声器播放完成”。
- 姿态推理启动日志使用内置 `bus.jpg`，不能视作摄像头已接入或已获得实时图像。
