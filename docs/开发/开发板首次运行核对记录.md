## 串口与首次烧录

- 在用户连接主控板后，通过 Windows 串口列表与即插即用设备列表确认 COM7，未发现该设备的驱动异常。
- 最初以 115200 波特率被动读取约 6 秒收到 0 字节；随后通过串口控制线复位，已捕获启动日志。短时间没有日志不能据此判断固件未运行。
- esptool 实测芯片为 ESP32-S3 QFN56 rev 0.2，Flash 为 16 MB；启动日志显示 PSRAM 为 8 MB。
- 用户配置凭证后，本机检查 PID 为 11776、密钥为 32 个 ASCII 字符，无空白或遮罩字符，并确认新凭证已进入编译产物。此检查仅验证配置格式与构建结果，不代表云端鉴权成功；不记录密钥值。
- 在项目根目录执行 `.\src\firmware\dev.bat build` 成功，再执行 `.\src\firmware\dev.bat flashall -p COM7`，全部 6 个镜像烧录并通过哈希校验。没有执行整片擦除；烧录工具仅擦除写入镜像涉及的区域。
- 镜像地址：引导程序 `0x0`、分区表 `0x10000`、OTA 初始数据 `0x1d000`、PHY 初始数据 `0x1f000`、应用 `0x20000`、姿态模型 `0x810000`。
- 启动观察期间没有发现崩溃重启，音频引擎初始化成功，BLE 配网启动返回 0。设备没有已保存的 Wi-Fi 配置，尚未完成联网与云连接。

## 音频实测与排查

- **已确认原因与处理**：麦克风与喇叭插头接反，用户纠正后确认有声音，后续联网对话确认正常语音回答。接线按语音板实际 `MIC` / `SPK` 标识核对，不能只按插头外形或模糊照片判断。
- **代码回退**：排查期间曾增加设备就绪等待、延长开机音超时，编译烧录后仍无声，因此已撤回。`qm_audio_device_vb701n.c` 和 `boot_sound.c` 恢复为当时 SDK HEAD 原始内容；回退后构建与应用烧录、哈希校验通过，应用大小恢复为 `0x2f8f70`（3,116,912 字节）。当时本机产品凭证与既有 `dev.bat` 修复保留，后者随后提交团队分支。
- **音频链路证据**：UART1，主控 TX=GPIO40、RX=GPIO39，波特率 2000000，流控输入 GPIO38；VB701N 返回版本 `1.1.7` 并持续返回麦克风 PCM。日志音量 80，对应芯片档位 24/31。这证明串口通信与音频上行工作，实际发声仍以用户听音为依据。
- **时序排查的范围**：原流程约 3.13 秒发送开机音、4.15 秒完成初始化；等待就绪方案曾触发原有 1 秒队列超时，进一步延长超时后队列超时消失，但用户仍听不到声音。该推测没有解决本次问题，不能写为已修复缺陷；这些调整不属于当前代码。
- **日志解释**：`local play done ret=-6` 对应 `-QM_ENOSYS`，当前 VB701N 适配层未声明物理播放完成确认（DRAIN）能力；该值不能单独证明 PCM 未发送或喇叭损坏。姿态推理使用内置 `bus.jpg`，也不能视作摄像头已取得实时图像。

## 2026-10-29 更换网络后恢复配网

- 用户反馈：此前已在另一网络完成配网，更换网络后在小程序删除设备，再次搜索时无法发现。
- 实物照片中主板右侧按键标为 `BOOT` 和 `EN`，未确认存在接到 GPIO14 的独立配网按键。不能仅凭固件监听 GPIO14，就指示用户长按某个实体按钮；`EN` 普通重启不会清除 Wi-Fi，`BOOT` 不能直接当作配网键。
- 连接方式与供电：沿用照片中主板 USB 连接当前电脑、主板与语音板通过连接件相连的方式，未改动外设接线或供电方案。Windows 确认 CH343 串口为 COM7，状态 OK；串口 115200 实测持续输出 Wi-Fi 断开及重连日志。串口 `help` 仅列出基础命令与 `alarm`，没有清除配网配置的命令。
- 从设备读取的实际分区表确认 NVS 位于 `0x11000`，大小 `0xc000`（48 KB）；此前手册附录所列 `0x9000` 不能用于本设备的直接 Flash 操作。
- 已将实际分区表及原始 NVS 备份到本机 `%LOCALAPPDATA%\Codex\device-recovery\xjwb03-20261029\`，备份可能含网络与设备凭证，不纳入仓库。使用 SDK 自带 NVS 解析器校验页头和目标条目 CRC 后，仅将 `qm_kv` 命名空间下 `wifi_cfg` 的 blob 数据与索引条目标记为已删除；共改变 3 个条目状态位图字节。写回受影响的 `0x16000` 单个 4 KB 扇区，esptool 哈希校验通过。其他配置条目、应用固件及模型分区未改动，没有整片擦除或重新编译烧录应用。
- 重启实测：`system KV init ret=0`、`no saved wifi, start ble provision`、`ble provision start ret=0`，BLE 服务启动状态为 0。确认已恢复等待蓝牙配网；这次手机能否发现、使用新网络配网、重新绑定及连云仍待用户验证。
- 后续操作：在“灵机一动AI”添加设备，确认手机蓝牙及微信／小程序权限，使用新网络的 2.4 GHz Wi-Fi。此处记录的是本次有备份、有分区核对的恢复操作，不应对其他设备照抄固定 Flash 地址。
