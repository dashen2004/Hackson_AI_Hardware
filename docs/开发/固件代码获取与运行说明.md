## 获取与恢复代码

首次克隆本项目：

```powershell
git clone --recurse-submodules https://github.com/dashen2004/Hackson_AI_Hardware.git
Set-Location Hackson_AI_Hardware
```

已经有本项目工作区时，在项目根目录执行：

```powershell
git submodule update --init --recursive
git submodule status --recursive
```

初始化命令获取主仓库固定的 SDK 版本。日常同步主仓库后，再次执行该命令即可恢复对应依赖。

### Gitee HTTPS 认证失败时使用 SSH

本次环境中 Gitee HTTPS Git 接口返回 HTTP 401，已通过本机既有 SSH 配置获取代码。其他成员需要先在自己的 Gitee 账号配置 SSH 公钥，并确认服务器主机指纹，然后验证连接：

```powershell
ssh -T git@gitee.com
```

已有本项目工作区时，可只在本地配置该子模块的 SSH 地址，不修改共享的 `.gitmodules`：

```powershell
git submodule init
git config submodule.src/firmware.url git@gitee.com:xj-open/ljyd_xjwb03_agent_public_developer.git
git submodule update --init --recursive
```

如果 Git 自带 SSH 传输停滞，可在当前 PowerShell 窗口中改用 Windows OpenSSH 和 Gitee SSH 443 端口；本次环境通过此方式完成传输：

```powershell
$env:GIT_SSH_COMMAND = 'C:/Windows/System32/OpenSSH/ssh.exe -o Hostname=ssh.gitee.com -o HostKeyAlias=gitee.com -p 443 -o ServerAliveInterval=15'
git submodule update --init --recursive
Remove-Item Env:GIT_SSH_COMMAND
```

本机 SDK 的 `core.sshCommand` 也保存了这一连接方式，仅影响本地 SDK 仓库，不写入共享 Git 配置。

## 开发入口与版本管理

| 目的 | 相对项目根目录的位置 |
| --- | --- |
| 应用启动逻辑 | `src/firmware/apps/main/main.c` |
| 功能宏开关 | `src/firmware/apps/main/qm_config/qm_config.h` |
| 产品 PID 与密钥配置 | `src/firmware/apps/main/cloud/ljyd_cloud.h` |
| 板级外设 | `src/firmware/apps/main/peripheral/` |

子模块内部的修改需要在 SDK 仓库内单独提交，主仓库只记录 SDK 的提交引用。团队后续若修改固件，应将 SDK 提交推送到成员都能访问的仓库（可使用团队 fork，并同步调整 `.gitmodules`）；只提交主仓库的引用无法传递未推送的 SDK 修改。项目的具体固件功能与团队 fork 地址待确认。

实际 PID、密钥及平台环境待配置；不要把项目真实密钥提交到版本库。

## 后续安装与运行

在项目根目录打开 PowerShell，进入 SDK 目录，按上游说明安装工具链并编译：

```powershell
Set-Location src/firmware
.\install.bat
.\dev.bat build
```

此处列出后续操作步骤；本次获取代码未执行安装脚本或编译。工具链安装会下载开发工具并准备 Python 环境。编译产物按上游说明位于 `apps/build/`。

硬件适用型号为 XJWB03-DevKIT-V1 底板与 LJX40-Audio-KIT-V1 语音模块，实际套件型号待核对。接线、供电要求、串口识别、PID 配置、首次全量烧录与配网步骤，统一参见[开发板使用文档](../硬件/开发板/灵机XJWB03标准开发板使用文档.md)。本次不涉及接线或烧录，尚未进行实物验证。
