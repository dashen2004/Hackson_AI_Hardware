## 获取与恢复代码

首次克隆本项目：

```powershell
git clone --recurse-submodules https://github.com/dashen2004/Hackson_AI_Hardware.git
Set-Location Hackson_AI_Hardware
```

已经有本项目工作区时，在项目根目录执行：

```powershell
git submodule sync --recursive
git submodule update --init --recursive
git submodule status --recursive
```

初始化命令获取主仓库固定的 SDK 版本。日常同步主仓库后，再次执行该命令即可恢复对应依赖。

### GitHub 认证与上游 Gitee 获取记录

主仓库和 SDK 分支均位于同一个私有 GitHub 仓库，团队成员需具备该仓库的读取权限。已有工作区必须先执行上述 `git submodule sync --recursive`，将此前的 Gitee 子模块地址同步为 GitHub 地址。GitHub HTTPS 认证由本机 Git 凭证管理器处理，不在文档或 Git URL 中保存令牌。

以下是 2026-10-22 获取官方上游时的历史记录；团队日常获取应使用上面的 GitHub 地址，不再将子模块改回 Gitee。

本次环境中 Gitee HTTPS Git 接口返回 HTTP 401，已通过本机既有 SSH 配置获取代码。其他成员需要先在自己的 Gitee 账号配置 SSH 公钥，并确认服务器主机指纹，然后验证连接：

```powershell
ssh -T git@gitee.com
```

需要单独获取官方上游时，可在其他目录克隆，不修改团队工作区的子模块地址：

```powershell
git clone git@gitee.com:xj-open/ljyd_xjwb03_agent_public_developer.git ljyd-upstream
```

如果 Git 自带 SSH 传输停滞，可在当前 PowerShell 窗口中改用 Windows OpenSSH 和 Gitee SSH 443 端口；本次环境通过此方式完成传输：

```powershell
$env:GIT_SSH_COMMAND = 'C:/Windows/System32/OpenSSH/ssh.exe -o Hostname=ssh.gitee.com -o HostKeyAlias=gitee.com -p 443 -o ServerAliveInterval=15'
git clone git@gitee.com:xj-open/ljyd_xjwb03_agent_public_developer.git ljyd-upstream
Remove-Item Env:GIT_SSH_COMMAND
```

本机 SDK 的 `core.sshCommand` 也保存了这一连接方式，仅影响本地 SDK 仓库，不写入共享 Git 配置。

## 工具链安装与运行

本项目提供 PowerShell 安装与环境激活入口。在项目根目录打开 PowerShell，首次安装执行：

```powershell
.\tools\Install-FirmwareTools.ps1
```

脚本调用 SDK 内置的 `esp-idf/tools/idf_tools.py`，按其版本清单安装 ESP32-S3 所需工具，再按照官方约束文件安装 Python 依赖。已有 Git 和 Python 3 为前置条件；本机使用 Python 3.12.10。下载 GitHub 发布包时默认使用 Espressif 官方镜像；仅在安装进程中设置镜像，结束后恢复原值。重复运行会复用已安装工具。默认工具目录为 `%USERPROFILE%\.espressif`；如需自定义位置，安装和激活前应设置同一个 `IDF_TOOLS_PATH`。

每次打开新 PowerShell 窗口后，从项目根目录激活环境，再执行编译：

```powershell
# 如果执行策略阻止本地脚本，仅对当前窗口放行：
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# 注意开头的点号和空格，使环境在当前窗口生效。
. .\tools\Enter-Firmware.ps1
idf.py --version
idf.py -C src/firmware/apps build
```

激活入口使用官方 `activate.py` 自动定位 Python 虚拟环境和工具版本，设置本项目的 `IDF_PATH`、`ADF_PATH`，并将路径转为 QUMIOS CMake 所需的正斜杠格式。它不调用上游 ADF 补丁脚本，不自动修改 SDK 源码，也不修改系统或用户的永久 `PATH`。

2026-10-23 已修复 `src/firmware/dev.bat`：将原来写死的 Python 3.14 环境和工具版本路径替换为 SDK 官方激活器自动发现，可直接执行以下命令，无需预先激活 PowerShell 环境：

```powershell
Set-Location src/firmware
.\dev.bat build
```

此修复已提交到团队 SDK 分支，应用启动流程注释也一并纳入版本管理；真实产品凭证仍仅保留在本机。编译产物位于 `src/firmware/apps/build/`。

工具版本、验证结果和使用限制见[Windows 工具链安装记录](Windows工具链安装记录.md)。

硬件适用型号为 XJWB03-DevKIT-V1 底板与 LJX40-Audio-KIT-V1 语音模块，实际套件型号待核对。接线、供电要求、串口识别、PID 配置、首次全量烧录与配网步骤，统一参见[开发板使用文档](../硬件/开发板/灵机XJWB03标准开发板使用文档.md)。本次不涉及接线或烧录，尚未进行实物验证。
