# 将按钮接入设备插件

先确定按钮所在端、目标动作、当前发布的产品／智能体版本和插件协议。以该插件的官方文档、当前平台配置和实际 SDK 为准；不要把一个插件的 `method`、`subMethod` 或状态规则套用到其他插件。

## 选择控制路径

- **小程序／H5 面板按钮**：使用平台支持并经过授权的控制接口或现有小程序桥接，将按钮动作交给平台，再由平台向设备下发指令或物模型属性。核对接口的设备身份、权限、参数与返回值。浏览器页面不能冒充设备向 `device/up` 发消息，也不能只在前端拼一条 `device/down` JSON 就声称平台已经控制设备。
- **设备本地按键**：消抖和区分短按／长按后，在普通任务上下文执行本地动作；按目标插件协议上报本地事件。ISR、计时器回调和网络回调中不要做阻塞 MQTT 发布。离线、重连和上报失败时保留真实设备状态并按现有同步机制重报。

把“请求已提交”“设备已执行”“平台状态已同步”分开验收。端侧先确认实际动作结果，再回执成功；失败回执不能伪装成功。避免本地上报经平台回环后再次执行或重复上报。

## 本项目的番茄钟

在改 Ticko 专注按钮前，阅读 [番茄钟协议与项目边界](references/ticko-pomodoro.md)。明确按钮要控制原生番茄插件的学习模式，还是 `12 focusTimer` 自定义计时；两者当前共享计时组件，但云端禁闲聊语义不同。按钮若需要指定时长，必须传递明确的秒数并验证设备采用该值，不得悄悄改用固件开发默认值。

## 验收

对目标按钮验证一次完整链路：点击或按下 → 平台接口受理 → 设备收到并执行 → 状态／回执与真实计时或硬件一致 → 该插件需要时，云端状态也随本地开始、停止及自然结束变化。对失败、重复触发、离线重连和回环做有针对性的检查。设备实物、平台调用和主机替身分别记录；没有实物或平台证据时，只报告已验证的层级。
